`@antelopejs/interface-dms-builder` creates and edits DMS pages from a backend module or a tool. The operations write ordinary TypeScript into your project. No separate database holds page definitions.

To edit a page with the mouse instead, start with the [visual builder guide](https://dms.antelopejs.com/docs/modules/builder/introduction).

## Quick start

This example creates a **Revenue** page with a **Total revenue** card. It runs once from a backend module after the builder is available, in a development project that loads `@antelopejs/dms`, which implements the builder in development. The interface package alone does not provide the implementation.

The project must already have a `pages` category. `ListCategories()` lists yours, and [Create a category](./4.page-operations.md#create-a-category) adds one. The page name must be unused, because a second creation with the same name returns `duplicate_name`.

```typescript
import {
  AddBlock,
  CreatePage,
} from "@antelopejs/interface-dms-builder";

const page = await CreatePage({
  name: "revenue",
  displayName: "Revenue",
  category: "pages",
  icon: "i-ph-chart-line",
});
if (!page.ok) {
  throw new Error(`could not create the page: ${page.error.code}`);
}

const block = await AddBlock({
  page: page.data.ref, // "/revenue"
  name: "total",
  type: "KpiCard",
  config: {
    title: "Total revenue",
    icon: "i-ph-currency-eur",
  },
});
if (!block.ok) {
  throw new Error(`could not add the block: ${block.error.code}`);
}

console.log(block.data.path); // "/revenue#total"
for (const change of block.changes) {
  console.log(change.kind, change.path);
}
```

After the backend reloads, a tenant owner who opens `/revenue` sees the page and its card. The card has no revenue data yet. [Queries](./6.queries.md) connects a card to a resource for real numbers.

Each call saves on its own. If `CreatePage` succeeds and `AddBlock` fails, the empty page stays. Fix the block configuration and retry that call, not the page creation.

## How an edit reaches your files

A *block* is one DMS component, such as a card or a table. Adding one writes a factory call into a `PageController` class, either as a static field or as a child of another block. The builder parses the source, stages the edit in memory and typechecks the whole project before it writes. A type error anywhere in the project outside `node_modules` can therefore block the edit.

Operations are `InterfaceFunction` exports from `@antelopejs/interface-core`. An expected failure comes back as a value you can inspect:

```typescript
// Success: { ok: true, data, changes, warnings? }
// Failure: { ok: false, error }
```

Listing operations such as `ListPages` return their value directly. [Results and errors](./8.results-and-errors.md) holds the full contract. When you read before you write, pass the structure's `version` as `expectedVersion`, so that the write fails instead of overwriting another editor's work.

A caller that picks an operation by name, such as a route that forwards a request, reads `Operations`. It holds every operation under its exported name, with its own parameter and result types. `OperationName` is the union of those names.

Hand-written declarations stay editable when the builder recognizes their shape. Otherwise the builder marks them *opaque*. You can inspect an opaque block, and the builder refuses to rewrite code it does not understand. [Drafts and preview](./9.drafts-and-preview.md) saves a whole block tree in one transaction.
