The components of a DMS page mount independently, yet they often react to one another. A form disables a field when a checkbox changes, and a table reads its rows again after a form saves. The DMS connects them without props or a shared store, through three parts:

- **An event bus.** `useComponentEvent` dispatches a `CustomEvent` on `window`. Any component can send one, and any component can listen.
- **A function registry.** `useDefinedFunctions` maps a string id to a handler that the frontend registers once.
- **A watch engine.** `useWatch` reads the `watchActions` a component carries, which the backend declares. It listens to the events they name, and on a match it calls the registered handler.

The backend declares, as plain data, "when event E fires on component C and its payload matches, run function F". The frontend runs it, with no frontend code per page.

```text [From a declaration to a visible change]
Backend .watch()
            │ watchActions
            ▼
┌───────────────────────┐
│ Browser: useWatch     │◀── Event
│ checks id, event      │
│ and payload           │
└───────────┬───────────┘
            │ match
            ▼
┌───────────────────────┐
│ Registered handler    │
│ mutates state         │
└───────────┬───────────┘
            ▼
Component renders state
```

The event stays in the browser. A handler may request data, but sending an event calls no backend route and grants no permission.

::note
This page covers the frontend half. The backend half, the `.watch()` and `.watchOn()` builder methods and the events each component emits, is in [Actions & reactivity](/docs/building/actions-and-reactivity).
::

## The event bus

`useComponentEvent` returns `sendComponentEvent(name, componentId, data?)`, which dispatches a `CustomEvent` on `window`. Listeners subscribe to the event `name`. The `componentId` names the sender, and listeners filter on it. The `data` is the payload. The event's `detail` is `{ component, data }`.

```ts fragment [Sending an event]
const { sendComponentEvent } = useComponentEvent();
sendComponentEvent("DmsComponent.Form.FieldChange", componentId, {
  fieldId: "isOwner",
  value: true,
});
```

`useComponentEvent(componentId)` with a `componentId` also sends two lifecycle events: `Events.LOAD` (`"DmsComponent.Load"`) on mount and `Events.UNLOAD` (`"DmsComponent.Unload"`) before unmount. Other components can react to yours appearing or leaving. Call `useComponentEvent()` with no argument to send only.

## The function registry

`useDefinedFunctions` returns one registry shared by the whole app:

```ts fragment
const { registerFunction, getFunction, unregisterFunction } = useDefinedFunctions();
```

| Function                     | Does                                                                 |
| ---------------------------- | -------------------------------------------------------------------- |
| `registerFunction(id, fn)`   | Registers `fn` under `id`. A second registration under the same `id` replaces the first. |
| `getFunction(id)`            | Returns the function registered under `id`, or `undefined`.          |
| `unregisterFunction(id)`     | Removes the function registered under `id`.                          |

An id is a plain string. The backend names a function in a watch-action, and the frontend registers a handler under the same string. Type the handler as a `WatchActionFunction`, `(action, eventData, componentState) => void`. Register your own from a plugin in your [frontend layer](/docs/building/frontend-layer).

## Reacting with `useWatch`

A component that reacts to events calls `useWatch(actions, componentId?, defaultState?)`. On mount, `useWatch` adds a `window` listener for each distinct `action.event`, and it removes them on unmount. It returns `isLoading` and `state`.

Each action is a `WatchAction`, exported from `@antelopejs/interface-dms/watch-actions`:

| Field                | Type                                               | Notes                                                                 |
| -------------------- | -------------------------------------------------- | --------------------------------------------------------------------- |
| `component`          | `string`                                           | The id of the component that sends the event.                        |
| `event`              | `string`                                           | The event name.                                                       |
| `functionId`         | `string`                                           | The id of the registered function to run.                             |
| `params?`            | `Record<string, unknown>`                          | Parameters for the function, read from `action.params`.               |
| `onParam?`           | `WatchActionCondition \| WatchActionCondition[]`   | Conditions on the event's payload (below).                            |
| `requirePermission?` | `string`                                           | The server drops the action from the page for a caller without this permission. |

An action matches an event when all of these hold:

- `action.component` equals the sender's id. `ComponentId.SELF` (`"$component:self"`) stands for the watcher's own `componentId`, so a component can watch its own events.
- `action.event` equals the event's type.
- The `onParam` conditions pass.

On a match, `useWatch` looks up `getFunction(action.functionId)` and calls it as `fn(action, event.detail, state)`. `state` is a `ref` that starts as `defaultState`. The handler changes `state`, and the component reads it reactively.

A handler that throws does not stop the other matched actions for that event. An action whose function is not registered is skipped. `isLoading` is `true` while the handlers run.

### `onParam` matching

`onParam` filters on the event's payload. Each condition pairs a `key`, a dotted path read from `event.detail.data`, with a `value` compared with strict equality. In an array, every condition must pass:

```ts [Only when isOwner becomes true]
import type { WatchActionCondition } from "@antelopejs/interface-dms/watch-actions";

export const ownerTurnedOn: WatchActionCondition[] = [
  { key: "fieldId", value: "isOwner" },
  { key: "value", value: true },
];
```

One stream of `FormEvents.FIELD_CHANGE` events can then drive different reactions for different fields and values.

## `useEventedAction`

`useEventedAction` is the sending half. It wraps an async operation, sets a loading flag, and sends start, success and error component events around it, so other components can watch the operation.

```ts fragment
const { execute, isLoading } = useEventedAction<FormSubmitResponse>({
  componentId: props.componentId,
  events: {
    start: FormEvents.SUBMIT,
    success: FormEvents.SUBMIT_SUCCESS,
    error: FormEvents.SUBMIT_ERROR,
  },
});
```

`execute(action, options?)` sets `isLoading`, sends `start`, and awaits `action()`. On success it sends `success` and returns the result. On failure it sends `error` and throws the error again. It clears `isLoading` in both cases. The optional `startPayload`, `successPayload(result)` and `errorPayload(error)` set the data of each event. An event is sent only when both its name and the `componentId` are set.

## Refreshing the blocks of a page

`refreshPageBlocks()`, a util of the UI layer, asks every data block mounted on the page to read its data again. The blocks are `StatGroup`, `KeyValueList`, `NavCardGrid`, `ActivityFeed`, the KPI, top-list and meter cards, a `Banner` with a `fetchUrl`, the charts, a tab set's badges and the table views. The reads that a component of the page makes through `useApiData` or `useDmsAsyncData` run again too, unless they set `refreshOnPageRefresh: false`. A block keeps what it shows until the new answer arrives, and it does not remount. The call returns a promise that resolves once those reads are done, failed reads included.

Call it from a component of your own after its action changed the record the page shows:

```ts fragment [app/components/RefundButton.vue]
async function refund() {
  await $authFetch(`/api/invoices/${props.routeParams?.id}/refund`, { method: "POST" });
  await refreshPageBlocks();
}
```

The page header calls it after a button changed something, and the built-in watch function `BlockFunctions.REFRESH_PAGE` calls it from a watch-action ([Actions & reactivity](/docs/building/actions-and-reactivity#built-in-function-ids)). On a page declared with `live`, it reads even while the page is paused. It works through a window event, `BLOCK_REFRESH_EVENT` (`"DmsComponent.Block.Refresh"`).

## End-to-end example

In this example, a change of a form field writes a flag into the form's state. It takes two parts that share one id.

First, the frontend registers the handler in a plugin of your frontend layer:

```ts fragment [app/plugins/register-app-functions.ts]
const markOwner: WatchActionFunction = (_action, eventData, componentState) => {
  const data = eventData.data;
  componentState.value.isOwnerSelected =
    typeof data === "object" && data !== null && "value" in data && data.value === true;
};

export default defineDmsPlugin(() => {
  useDefinedFunctions().registerFunction("app.form.MarkOwner", markOwner);
});
```

Then the backend declares the watch-action on the component. `.watch(event, functionId, options)` records an action with `component: ComponentId.SELF`, so the form listens to the events it sends itself:

```ts [src/pages/profile.ts]
import { PageController, RegisterPage, pagesCategory } from "@antelopejs/interface-dms/page";
import { Form, FormEvents } from "@antelopejs/interface-dms/base/form";
import { DefaultDataTypes } from "@antelopejs/interface-dms/base/data-types";

@RegisterPage()
export class ProfilePage extends PageController("profile", {
  displayName: "Profile",
  icon: "i-ph-user",
  category: pagesCategory,
}) {
  static form = Form({
    title: "Profile",
    fields: [
      { id: "isOwner", label: "Is owner", type: new DefaultDataTypes.BooleanType() },
      { id: "displayName", label: "Display name", type: new DefaultDataTypes.StringType() },
    ],
  }).watch(FormEvents.FIELD_CHANGE, "app.form.MarkOwner", {
    onParam: { key: "fieldId", value: "isOwner" },
  });
}
```

The form sends `FIELD_CHANGE` once for each field with the value it starts from, then on each change. Each time `isOwner` is the field, `useWatch` finds the `onParam` match, looks up `app.form.MarkOwner` in the registry and runs it, which sets `state.isOwnerSelected`. Conditional fields work the same way with a built-in `functionId` such as `FormFunctions.SET_FIELD_HIDDEN`. A function of your own adds a handler under a new id.
