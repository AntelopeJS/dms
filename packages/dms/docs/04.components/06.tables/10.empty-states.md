# Empty states

A table view with no row to show says why: it has no row yet, its filters match nothing, or the list failed. `emptyStates` replaces the built-in words for each of those reasons with the module's own — "No campaign sent yet", "No run matches {search}" — and adds links, while the table keeps its own actions in front.

```ts [src/pages/campaigns.ts]
static campaigns = TableView(campaignDataAPI, {
  caption: "Campaigns",
  emptyStates: {
    firstRun: {
      title: "$mailing.campaigns.empty_title",
      description: "$mailing.campaigns.empty_description",
      icon: "i-ph-paper-plane-tilt",
      actions: [{ label: "$mailing.campaigns.guide", to: "https://antelopejs.com/docs" }],
    },
    filtered: {
      title: "$mailing.campaigns.no_match", // "No campaign matches “{search}”"
    },
  },
});
```

## The three states

| State      | Shown when                                                    | The table's own action, kept in front                                       |
| ---------- | ------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `firstRun` | The table has no row yet.                                     | **New entry**, when the caller may add.                                     |
| `filtered` | A search, a filter, a quick filter or an active `queryParamFilters` filter matches nothing. | **Clear filters**, **Clear search** or **Clear filters and search**.        |
| `error`    | The list request failed.                                      | **Try again**.                                                              |

A state left out keeps the built-in texts. The archive view of a table in [archive mode](/docs/components/tables#archive-mode) keeps its own words and its "show active rows" action.

Each state is a `TableViewEmptyState`:

| Field         | Type                | Purpose                                                                                            |
| ------------- | ------------------- | -------------------------------------------------------------------------------------------------- |
| `title`       | `string`            | Title of the state. Required.                                                                      |
| `description` | `string`            | Text under the title.                                                                              |
| `icon`        | `string`            | Icon in the well; defaults to the built-in icon of the state.                                      |
| `actions`     | `BlockLinkAction[]` | Link buttons, after the table's own action: `{ label, to, icon?, color?, variant? }`.              |
| `component`   | `Component`         | A frontend component drawing the whole state instead (below).                                      |

Texts are i18n keys (`$`) or literals. Both receive `{ search }`, the text the user searched: a key's translation as a parameter, a literal by its `{search}` placeholder (a placeholder naming nothing else stays as written). Action labels receive no parameter.

## A component of your own

`component` replaces the whole state — a gallery of templates to start from, an onboarding checklist. It is resolved by name from the global frontend registry and receives its own options, plus:

| Prop      | Type                                   | Purpose                                     |
| --------- | -------------------------------------- | ------------------------------------------- |
| `state`   | `"firstRun" \| "filtered" \| "error"`   | Why the table is empty.                     |
| `search`  | `string`                               | The text searched, empty when none.         |
| `refresh` | `() => void`                           | Lists the rows again.                       |

```ts
emptyStates: {
  firstRun: { title: "$mailing.templates.empty_title", component: CustomComponent("TemplateGallery") },
},
```

The table's own actions are not drawn around a component: it offers what it needs itself.

## Other displays

The built-in `cards` display shows the same empty states as the grid. The kanban board and a module's [custom display](/docs/extending-the-dashboard/table-view-displays) draw their own empty body.
