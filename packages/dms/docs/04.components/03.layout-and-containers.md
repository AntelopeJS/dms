# Layout & containers

Layout components render no data of their own — [Guard](#guard) reads a route only to decide whether its children show. They arrange **other** components — the [forms](/docs/components/forms), [tables](/docs/components/tables), [charts & widgets](/docs/components/charts-and-widgets) you attach to a page. Every declared position still carries its own permission: the page's container field, each nested row or stack, and each leaf append their id to the path. A role needs every level it should render; granting the container alone does not expose its children.

Each is a plain component builder, so it composes like every builder does (see [Pages & components](/docs/building/pages-and-components)). You nest with `.child()`:

```ts [signature]
.child(id: string, component: Component, metadata?: { slot?: string; [key: string]: unknown }): this
```

`id` is the child's key under that parent (must be unique — a duplicate logs a warning). `component` is any other builder, so nesting is arbitrary. `.child()` returns the parent, so calls chain into a serializable tree the shared frontend renders. `metadata` carries per-child data: [Tab](#tab) uses `{ slot }`, [Grid](#grid) rows accept `{ colSpan }`; otherwise it is ignored.

::note
**Grid is the one container with a shape rule:** a `Grid`'s direct children must be `GridRow`s, with the leaf components inside the rows. Stacks and tabs take any component as a direct child.
::

## Grid

**What it renders** — a CSS grid. Each `GridRow` becomes a row; its children spread across equal-width columns. The column count is derived from the densest row, so a two-item and a three-item row in the same grid align to a three-column track. `gap` spaces both rows and columns. Columns never shrink below `minColumnWidth` (240px by default): when the grid is narrower than the widest row needs, it drops columns and the cells wrap, down to one column on a phone.

**Import**

```ts [src/pages/dashboard.ts]
import { Grid, GridRow } from "@antelopejs/interface-dms/base/grid";
```

**Options**

| Option           | Type     | Default   | Purpose                                            |
| ---------------- | -------- | --------- | -------------------------------------------------- |
| `gap`            | `string` | `"1rem"`  | CSS gap between rows and columns.                  |
| `minColumnWidth` | `string` | `"240px"` | Narrowest a column gets before the grid drops one. |

`GridRow()` takes no options — it is a pure row marker.

**Features**

- Column count auto-computed from the widest row; rows may differ in length.
- A row child can span columns with child metadata: `.child("wide", …, { colSpan: 2 })`. A span never exceeds the columns left at the current width, so a `colSpan: 3` cell takes the single column of a phone instead of pushing the row off screen.
- A `Spacer` in a row holds an empty cell, to line the next cells up with the columns. Once the grid has dropped columns there is nothing to line up with, so the spacer hides rather than taking a row of its own.
- The responsive behaviour is pure CSS (container queries on the grid's own width), so the server-rendered page is already laid out the way the browser keeps it.
- Any builder may sit inside a row, including stacks, tabs, or a nested grid.

## HStack / VStack / Spacer

**What it renders** — a flexbox container. `HStack` lays children left-to-right, `VStack` top-to-bottom. `alignment` controls the cross-axis (perpendicular line-up), `distribution` the main-axis (how free space is shared), and `spacing` the gap between children. `HStack` can additionally `wrap` overflowing children. A `Spacer` between children expands to absorb leftover space — e.g. logo · `Spacer` · actions pins the logo left and the actions right.

**Import**

```ts [src/pages/layout.ts]
import { HStack, VStack, Spacer } from "@antelopejs/interface-dms/base/stack";
```

**Options** — `HStackOptions` and `VStackOptions` share `alignment`, `distribution`, and `spacing`; only `HStack` adds `wrap`.

| Option         | Type                | Default    | Purpose                                         |
| -------------- | ------------------- | ---------- | ----------------------------------------------- |
| `alignment`    | `StackAlignment`    | `"center"` | Cross-axis alignment of children.               |
| `distribution` | `StackDistribution` | `"start"`  | Main-axis distribution of children.             |
| `spacing`      | `string`            | `"8px"`    | CSS gap between children.                       |
| `wrap`         | `boolean`           | `false`    | `HStack` only — wrap children to the next line. |

`StackAlignment` is `"start" | "center" | "end" | "stretch"`. `StackDistribution` is `"start" | "center" | "end" | "space-between" | "space-around" | "space-evenly"`.

`Spacer` is a flexible gap that works in either stack direction:

| Option    | Type     | Default     | Purpose                                     |
| --------- | -------- | ----------- | ------------------------------------------- |
| `grow`    | `number` | `1`         | Flex-grow weight — how greedily it expands. |
| `minSize` | `string` | `undefined` | Minimum size (CSS unit).                    |
| `maxSize` | `string` | `undefined` | Maximum size (CSS unit).                    |

**Features**

- Nest freely: stacks inside stacks build full scaffolds (header / sidebar / content / footer).
- `Spacer` respects its `minSize` / `maxSize` bounds.
- `alignment: "stretch"` makes children fill the cross axis — handy for equal-width cards in a row.

## Tab

**What it renders** — a tab strip plus a panel area. Each `TabItem` is a clickable tab with a `label`, `slot`, and optional `icon`, `badge`, `avatar`, keyboard `shortcut`, and `disabled` state. The active tab shows the children whose `.child(…, { slot })` matches its `slot`.

**Import**

```ts [src/pages/tabs.ts]
import { Tab, TabVariant } from "@antelopejs/interface-dms/base/tab";
```

**Options (`TabProps`)**

| Option          | Type             | Default      | Purpose                                                           |
| --------------- | ---------------- | ------------ | ----------------------------------------------------------------- |
| `items`         | `TabItem[]`      | _required_   | The tabs (see fields above).                                      |
| `color`         | `Color`          | `neutral`    | Accent color (`neutral`, `primary`, `success`, …); page-level navigation passes `primary`. |
| `size`          | `Size`           | `md`         | Tab sizing (`tiny`…`huge`, i.e. `xs`…`xl`).                       |
| `variant`       | `TabVariant`     | `pill`       | `pill` or `link` styling.                                         |
| `orientation`   | `AxeOrientation` | `horizontal` | `horizontal` or `vertical` strip.                                 |
| `fit`           | `boolean`        | `false`      | A horizontal `pill` list as wide as its tabs instead of the full width; a `link` list already sizes its tabs to their labels. |
| `unmountOnHide` | `boolean`        | `true`       | Destroy an inactive panel's children rather than keep them alive. |
| `persistState`  | `boolean`        | `false`      | Keep the selected tab in the URL query, so a reload or a shared link opens it. |
| `stateKey`      | `string`         | `"tab"`      | Query parameter holding the selected tab's index.                 |
| `badgesUrl`     | `string`         | —            | Route answering `{ [slot]: string \| number }` in one request: each replaces its tab's `badge`, shown like a table view's tab counts; fetched again when a `watchActions` entry fires or the page refreshes its blocks. Accepts `{{params.X}}` / `{{query.X}}`. |
| `realtimeTopic` | `string \| string[]` | — | Realtime topic(s); `badgesUrl` is read again when the backend publishes on one. |

A child binds to a tab by slot: `.child("overview", Form({ … }), { slot: "overview" })`; the item's `slot` and the child's `slot` must match. `Color`, `Size`, and `AxeOrientation` come from `@antelopejs/interface-dms/base/types`.

**Tab counts.** A record's tabs often count what each holds — 12 members, 1,284 invoices. Set `badgesUrl` to a route answering every count in one request, keyed by tab slot: each value replaces that tab's static `badge` (a number is formatted for the user's locale), drawn as a mono counter like a table view's tab counts. A tab the answer leaves out keeps its `badge`. The route is called again whenever one of the tab set's `watchActions` fires, or the page asks its blocks to refresh ([`BlockFunctions.REFRESH_PAGE`](/docs/components/display-blocks#live-items)), so a count follows the edits made on the page. On a record's page the route names the record: `{{params.X}}` is the route parameter `X` of the page URL, `{{query.X}}` its query parameter; nothing is requested while a token has no value, and the static badges show.

```ts [src/pages/workspace.ts]
static tabs = Tab({
  items: [
    { label: "Overview", slot: "overview" },
    { label: "Members", slot: "members", badge: "…" },
    { label: "Invoices", slot: "invoices", badge: "…" },
  ],
  badgesUrl: "/api/workspaces/{{params.id}}/tab-counts", // answers { members: 12, invoices: 1284 }
});
```

**Features**

- Per-tab icons, badges, avatars, and keyboard shortcuts.
- `unmountOnHide` selects keep-alive vs. rebuild-on-show for hidden panels.
- `persistState` + `stateKey` keep the user on the same tab across navigation.
- `fit: true` keeps a switch of a few short pill tabs ("Activity · Logins") to their labels' width, instead of stretching them across a wide card.
- Tabs emit a change event (`TabEvents.TAB_CHANGE`) other components can watch ([Actions & reactivity](/docs/building/actions-and-reactivity#events-components-emit)).

## Guard

**What it renders** — its children, unchanged, unless a route says there is nothing for them: then one [`EmptyState`](/docs/components/display-blocks#emptystate) — the `fallback` — in their place. A tab of charts about a route never called draws "No calls yet" and a link to call it, rather than a page of empty charts; the blocks of a record that is gone give way to one "Not found" rather than each failing on its own. The guard adds no box of its own (`display: contents`), so its children lay out as if it were not there.

**Import**

```ts [src/pages/routes.ts]
import { Guard } from "@antelopejs/interface-dms/base/guard";
```

**Options (`GuardOptions`)**

| Option           | Type                     | Default   | Purpose |
| ---------------- | ------------------------ | --------- | ------- |
| `fetchUrl`       | `string`                 | required  | The route read, with the `{{params.X}}` / `{{query.X}}` tokens of a block's `fetchUrl`. |
| `fetchUrlMethod` | `HttpMethod`             | `GET`     | Method of the request. |
| `periodScope`    | `string`                 | —         | Id of the `PeriodSelector` the route is read with, again on each change. |
| `realtimeTopic`  | `string \| string[]`     | —         | Topics whose events make the guard read the route again. |
| `when`           | `"empty" \| "notFound"`  | `"empty"` | `empty`: the value at `field` is absent, `null`, `false`, `0`, `""` or `[]`. `notFound`: the route answers 404. |
| `field`          | `string`                 | —         | Dot path of the value `empty` checks (`calls`, `summary.calls`); the whole answer without it. |
| `fallback`       | `GuardFallback`          | see below | An `EmptyState`'s options, all optional. Its title defaults to "Nothing to show yet", or for `notFound` to the [not-found state of a block](/docs/components/display-blocks#not-found), in the reader's language. |

**Features**

- The children show while the route loads, after any failure other than the condition (a 500, a timeout), and whenever the value is set. A realtime event, a new period or a page refresh that sets the value brings them back.
- The route is read like a block's data source: nothing is requested while a `{{params.X}}` / `{{query.X}}` token has no value, and the children show.
- For `notFound` the guard draws what a block whose source answers 404 draws: "Not found", the 404 body's `message` (an i18n key or a sentence) as its description, or a generic hint without one, and the same icon. `fallback` is laid over these defaults.
- An `emptyState` object in the answer — or in the body of the 404, for `notFound` — is laid over `fallback`, for what only the route knows: when the record was last used, or a link carrying its id (`actions: [{ label: "$api.routes.test", to: "/modules/api/routes?route=r1&tab=2" }]`).
- Any block may sit inside, and several: a `Grid`, a stack, a single chart. Only what is inside gives way — a toolbar or a table of attempts that should stay goes outside the guard.

A route's Statistics tab, which has nothing to chart until the route is called:

```ts [src/pages/routes.ts]
static details = Tab({
  items: [
    { label: "$api.routes.tabs.overview", slot: "overview" },
    { label: "$api.routes.tabs.statistics", slot: "statistics" },
    { label: "$api.routes.tabs.test", slot: "test" },
  ],
})
  .child("overview", RouteOverview(), { slot: "overview" })
  .child(
    "statistics",
    Guard({
      fetchUrl: "/api/routes/activity?route={{query.route}}", // { calls: 0, emptyState: { … } }
      periodScope: "api",
      realtimeTopic: "requests",
      field: "calls",
      fallback: {
        title: "$api.routes.statistics.idle_title",
        description: "$api.routes.statistics.idle_description",
        icon: "i-ph-moon-stars",
        actions: [{ label: "$api.routes.test", to: "/modules/api/routes?tab=2" }],
      },
    }).child(
      "charts",
      Grid({ minColumnWidth: "320px" })
        .child("summary", GridRow().child("stats", StatGroup({ /* … */ })))
        .child("charts", GridRow().child("status", ChartCard({ /* … */ })).child("latency", ChartCard({ /* … */ }))),
    ),
    { slot: "statistics" },
  )
  .child("test", RouteTester(), { slot: "test" });
```

The blocks of a detail page, for a record that may have been deleted:

```ts [src/pages/route-detail.ts]
static body = Guard({ fetchUrl: "/api/routes/{{params.id}}", when: "notFound" })
  .child("overview", KeyValueList({ fetchUrl: "/api/routes/{{params.id}}/summary" }))
  .child("activity", ActivityFeed({ fetchUrl: "/api/routes/{{params.id}}/activity" }));
```

## Placeholder

**What it renders** — a dashed, patterned box of the given `height` (and optional `width`) with its `label` centered. A development stand-in for blocking out a layout before the real components exist; it fetches nothing.

**Import**

```ts [src/pages/scaffold.ts]
import { Placeholder } from "@antelopejs/interface-dms/base/placeholder";
```

**Options (`PlaceholderOptions`)**

| Option   | Type     | Default     | Purpose                              |
| -------- | -------- | ----------- | ------------------------------------ |
| `label`  | `string` | `undefined` | Text shown inside the box.           |
| `height` | `string` | `"120px"`   | Box height (CSS unit).               |
| `width`  | `string` | `undefined` | Box width (CSS unit, auto if unset). |

**Features**

- Zero data dependencies — safe to drop anywhere to visualize spacing.
- Pairs naturally with stacks and grids while scaffolding a page.

::tip
Swap each `Placeholder` for its real builder as the page comes together.
::

## Composing a layout

Containers nest to build a whole screen. Here a `Grid` row splits the page into a sidebar and a tabbed detail panel, each blocked out with a `Placeholder` until its real builder exists:

```ts [src/pages/workspace.ts]
import { Grid, GridRow } from "@antelopejs/interface-dms/base/grid";
import { Placeholder } from "@antelopejs/interface-dms/base/placeholder";
import { Tab } from "@antelopejs/interface-dms/base/tab";

static layout = Grid({ gap: "1rem" }).child(
  "row1",
  GridRow()
    .child("files", Placeholder({ label: "Files" }))
    .child(
      "detail",
      Tab({
        items: [
          { label: "Overview", icon: "i-ph-info", slot: "overview" },
          { label: "Settings", icon: "i-ph-gear", slot: "settings" },
        ],
      })
        .child("overview", Placeholder({ label: "Overview" }), { slot: "overview" })
        .child("settings", Placeholder({ label: "Settings" }), { slot: "settings" }),
    ),
);
```

For dashboards, the same nesting feeds widgets — a `Grid` of `GridRow`s holding `KpiCard`s and `ChartCard`s. See [Charts & widgets](/docs/components/charts-and-widgets).
