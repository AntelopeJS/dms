# Prose

`Prose` draws long-form text written in Markdown: a guide, release notes, an onboarding page, terms to read. The text keeps a readable measure (about 72 characters a line) unless `width` is `wide`, takes its typography from the theme, and can list its headings in a table of contents (`toc`).

## Usage

```ts [src/pages/help.ts]
import { Prose } from "@antelopejs/interface-dms/base/prose";

// One text per locale.
static intro = Prose({
  toc: true,
  content: {
    "en-GB": "## Getting started\n\nImport your customers, then **invite your team**.",
    "fr-FR": "## Premiers pas\n\nImportez vos clients, puis **invitez votre équipe**.",
  },
});

// Or read from a route, in the reader's language.
static article = Prose({ fetchUrl: "/api/help/articles/{{params.slug}}" });
```

## Where the text comes from

| Source | When to use it |
| ------ | -------------- |
| `content: { "en-GB": "…", "fr-FR": "…" }` | **Recommended** for text written with the page: one Markdown text per locale. The reader's locale is read first, then one of the same language (`fr-BE` reads `fr-FR`), then the fallback locale, then the first text. |
| `fetchUrl` | **Recommended** for text stored elsewhere (a CMS, files, the database). The route answers `{ markdown }`; the request names the reader's language in its `x-content-language` header, and the block asks again when the reader switches language or the page [refreshes its blocks](/docs/components/block-fundamentals). `{{params.X}}` and `{{query.X}}` name the page URL. |
| `content: "## Plain Markdown"` | A text that needs no translation. |
| `content: "$help.intro"` | An i18n key. vue-i18n compiles its messages and reads `{`, `}`, `\|` and `@` as its own syntax, so the Markdown has to write them as literal interpolations: `{'{'}`, `{'}'}`, `{'\|'}`, `{'@'}` — a table's pipes included. Prefer a per-locale map. |

```ts [src/api/help.ts]
@Get("articles/:slug")
async article(
  @Parameter("slug") slug: string,
  @Parameter("x-content-language", "header") language?: string,
) {
  return { markdown: await readArticle(slug, language ?? "en-GB") };
}
```

While the first answer loads the block draws placeholder lines; a failure shows an error with a retry, and a 404 the [not-found state](/docs/components/block-fundamentals#not-found).

## What it draws

GitHub-flavoured Markdown:

- **Headings** — `##` to `####`, each with an anchor (`#getting-started`) shown on hover. A `#` heading is drawn as a `##`: the page already has its title. The table of contents lists the `##` and `###` headings, beside the text on a wide screen and above it on a phone.
- **Text** — paragraphs, **bold**, *italic*, ~~strikethrough~~, `inline code`, line breaks, horizontal rules.
- **Links** — a DMS route (`/orders/orders-list`) opens in place, an `#anchor` scrolls the page, `mailto:` and `tel:` open as usual, another site opens in a new tab with `rel="noopener noreferrer"`.
- **Lists** — ordered, unordered and task lists (`- [x] Done`), drawn with read-only checkboxes.
- **Quotes and callouts** — `> text` is a quote; `> [!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]` and `[!CAUTION]` on the quote's first line make a callout in the matching tone.
- **Code** — a fenced block is drawn like a [`CodeBlock`](/docs/components/display-blocks/code-block), highlighted in its language (` ```json `) with a copy button.
- **Tables** — with their column alignment; a wide table scrolls sideways.
- **Images** — `![Alt text](/media/files/chart.png "Caption")`: an image alone in its paragraph is a figure, its title the caption.

## Safety

The Markdown is read into tokens and drawn element by element — no HTML string is built or injected:

- **Raw HTML is never rendered.** A block of HTML is dropped; an inline tag is dropped and the text between tags is kept.
- **Only safe addresses become links or images**: `http(s)`, `mailto:`, `tel:`, a path or an `#anchor` for a link; `http(s)` or a path for an image. `javascript:`, `data:` and any other scheme are drawn as plain text.

The same parse runs on the server and in the browser, so the page hydrates without a jump.

## Pitfalls

- Do not put Markdown in an i18n message unless you escape it — see the table above. A per-locale map or a route is simpler.
- A link to another dashboard page is written as its path (`/billing/invoices`), not its full URL: a full URL opens in a new tab.
