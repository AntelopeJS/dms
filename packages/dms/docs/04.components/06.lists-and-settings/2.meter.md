# Meter

`Meter` draws an "x of y" bar: the label, a dimmed hint and the value on one line, the bar under it, then an optional legend. One value fills the bar in its tone; `segments` stack several fills, each with its legend label. `warnAt` and `errorAt` turn a single fill warning or error past a percentage of `max`.

::block-playground{type="Meter" height="160"}
---
options:
  label: Seats
  hint: 8 in use · 2 free
  max: 10
  legend: true
  card: true
  segments:
    - value: 6
      label: 6 members
    - value: 2
      tone: soft
      label: 2 pending invites
  actions:
    - label: Manage members
      to: /settings/members
---
::

## Usage

```ts [src/pages/workspace.ts]
import { Meter } from "@antelopejs/interface-dms/base/meter";

static storage = Meter({
  label: "$media.storage.label",
  fetchUrl: "/api/media/storage", // answers { value, max, valueLabel }
  warnAt: 80,
  errorAt: 95,
});
```

A meter is one measure, not a list: its route answers an object — any of `value`, `max`, `segments`, `hint`, `valueLabel` — rather than `{ items }`.

## Options

::block-options{type="Meter"}
::

| `format`   | Value text |
| ---------- | ---------- |
| `fraction` | `8 / 10`. The default. |
| `percent`  | `80%`      |
| `value`    | `8`        |
| `none`     | Nothing.   |

## Pitfalls

- `value` is ignored when `segments` is set.
- Figures that change per request (seats used, quota left) come from `fetchUrl`: a page layout is built once, when the page registers. The route answers an object (any subset of the meter's fields), not `{ items }`.
- The meter's source declares the `value` arrangement, so a no-code editor can generate one (a count or a sum over a table, answering `{ value }`) and offer it to whoever builds the page; the maximum then stays the meter's own `max`.
