# Page toolbar

`PageToolbar` is the bar a page with a period or live data starts with, under its header: "Updated 2 s ago · [● Live | ❚❚ Pause] · since yesterday 11:29 · vs Oct 16 … · [1H 24H 7D 30D]". It holds real blocks — a `LiveToggle`, a `PeriodSelector` and whatever a page puts on the left (a scope chip, a picker) — and draws them in one order and at one size, whatever order they were added in:

`[leading blocks…] · spacer · updated label · Live / Pause · window · vs window · comparison menu · presets`

On a narrow screen it wraps onto more lines, the controls staying on the right.

Every control in it is as tall as the others at its `size` — 24 px at `xs`, 28 px at `sm`, 32 px at `md`: the Live / Pause pill, the presets, the comparison menu, the refresh button. A bar is the same height on a live page, a page with a period only, and a page with both. A leading block of a module's own takes the same height from [`usePageToolbarSize()`](/docs/frontend-composables/page-context#usepagetoolbarsize).

  - id: period

## Usage

`pageToolbar()` builds one with the defaults every page shares, and a page puts it first:

```ts [src/pages/overview.ts]
import { CustomComponent } from "@antelopejs/interface-dms/base/custom";
import { pageToolbar } from "@antelopejs/interface-dms/base/page-toolbar";

@RegisterPage()
export class Overview extends PageController("overview", {
  displayName: "Overview",
  live: { maxRate: 5, rememberKey: "api" },
}) {
  static toolbar = pageToolbar({
    // Any block: a scope chip, a picker, a badge.
    leading: { scope: CustomComponent("ScopeChip") },
    live: { missedLabel: "$api.live.new_requests" },
    period: {
      id: "api",
      rememberKey: "api",
      // A menu: "vs previous period ▾".
      comparisons: ["previous-period", "previous-year", "none"],
    },
  });
  static kpis = /* … */;
}
```

| Option | Does |
| ------ | ---- |
| `leading` | The blocks on the left, keyed by child id, in order. The ids are the ones the roles editor shows. |
| `live` | The `LiveToggle` (child id `live`) over `PAGE_TOOLBAR_LIVE_DEFAULTS` — a pill, right aligned. `false` leaves it out. |
| `period` | The `PeriodSelector` (child id `period`) over `PAGE_TOOLBAR_PERIOD_DEFAULTS` — segmented 1H / 24H / 7D / 30D on the last 24 hours, the window written from now ("since yesterday 11:29"). With more than one comparison to choose from (`none` included, and the selector's default three), a "vs previous period ▾" menu between the window and the presets, on the first comparison besides `none`; with a single one, no control, the comparison kept on. A `custom` preset is its calendar icon alone, the window beside it writing the range. `false` leaves it out. |
| `size` | `xs`, `sm` (the default) or `md`: the size of the toggle, the selector, the window beside it and the refresh button, unless a child sets its own `size`. One height for all of them: 24, 28 or 32 px. |
| `showUpdatedAt`, `refresh` | Without a live toggle on screen: "Updated 12 s ago", and a ↻ button reading the page again. Both on by default. |

The children are ordinary blocks: `PageToolbar()` with `.child()` builds the same toolbar by hand, and a page builder finds its `LiveToggle` and `PeriodSelector` where they always were.

## Pages with and without `live`

- **A live page** (declared with [`live`](/docs/building/pages-and-components#live-pages-direct-and-pause)) shows the `LiveToggle` as always: "Updated 2 s ago", Live / Pause, the L key, "Paused · 40 new requests", Resume, the polling hint.
- **A page without `live`** has no Direct / Pause: the toggle draws nothing, and the toolbar shows when the page last read its data, with a refresh button. The time is the page's own: set when the page is shown, when its blocks read again on their events, and once a refresh (`refreshPageBlocks()`) is done.

```ts
// A report page: a period, no live data.
static toolbar = pageToolbar({ live: false, period: { id: "sales" } });

// A queue: live data, no period.
static toolbar = pageToolbar({ period: false });
```

The toolbar sits in the page body, first, like any block. It does not move into the page header.
