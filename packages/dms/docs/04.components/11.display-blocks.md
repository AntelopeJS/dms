# Display blocks

These blocks carry the summaries and notices around a page's data: a group of headline figures, label / value facts, a grid of cards linking elsewhere, an empty state, a banner, and a titled card holding other blocks. Each is a builder you declare on a page like any other ([Pages & components](/docs/building/pages-and-components)), and each is registered in the block catalog with its options described, so the page builder can place and configure it. The playground shows all of them under **Blocks**.

```ts [src/pages/overview.ts]
import {
  Banner,
  Card,
  EmptyState,
  KeyValueList,
  NavCardGrid,
  StatGroup,
} from "@antelopejs/interface-dms/base";
```

Every text option — titles, labels, details, button labels — follows the [`$`-prefix convention](/docs/frontend-composables/utilities#usetranslation--the--prefix-convention): `"$my_module.billing.title"` is translated, anything else is shown as written. Links (`to`) take a DMS route, an `#anchor` on the page, or an absolute URL, which opens in a new tab.

Tones are `neutral`, `primary`, `secondary`, `success`, `warning`, `error` and `info` (`Tone`, from `@antelopejs/interface-dms/base/types/tone`); an icon well also takes `muted`, the quiet well of a settings row. `color` is for what is clicked — buttons, row actions, header actions, tabs; `tone` is for what shows a state — pills, icon wells, banners, meters, notifications, these blocks.

## Live items

`StatGroup`, `KeyValueList` and `NavCardGrid` list items, like the [ActivityFeed](/docs/components/lists-and-settings#activityfeed). The items are written in the options, or read from a route with `fetchUrl`, which answers `{ items: [...] }` in the block's own item shape; in the page editor the route is picked in the data-source picker. While the first answer loads the block draws skeletons; when it fails it shows an error with a retry; when the list is empty it shows `empty`. Like the KPI cards, the block refetches when a [watched event](/docs/building/actions-and-reactivity) changes its state.

| Option           | Type                      | Purpose                                                   |
| ---------------- | ------------------------- | --------------------------------------------------------- |
| `fetchUrl`       | `string`                  | Route answering `{ items }`; replaces the static `items`. Accepts `{{params.X}}` / `{{query.X}}`. |
| `fetchUrlMethod` | `HttpMethod`              | Method of the fetch (`GET` by default).                   |
| `empty`          | `{ title, description? }` | Empty state shown when there is nothing to list.          |
| `skeletonCount`  | `number`                  | Placeholders drawn while `fetchUrl` loads. Optional.      |

A block cannot know how many items a route will answer before it answers, so its skeleton guesses: `columns`, or 4 cells for a `StatGroup`; 5 rows for a `KeyValueList`; `columns`, or 3 cards for a `NavCardGrid`. When the route usually answers a known number of items, set `skeletonCount` to it and the block keeps its height when they land. It is a count, not a height, so it holds at every width. Pages that leave it out render as before.

**The record of the page.** On a detail page the route names the record shown: `{{params.X}}` in `fetchUrl` is filled with the route parameter `X` of the page URL, `{{query.X}}` with its query parameter `X` — the tokens a [form's](/docs/components/forms) `fetchUrl` takes, `{{params.id:1}}` included. The block reads its route again when the page URL changes, and requests nothing while a token has no value: it shows `empty` instead of calling a route that does not exist. The same tokens work in the `fetchUrl` of the [charts and cards](/docs/components/charts-and-widgets) and the `badgesUrl` of a [`Tab`](/docs/components/layout-and-containers).

```ts [src/pages/workspaces/detail.ts — a page whose slug is `:id`]
static facts = KeyValueList({
  title: "Billing",
  fetchUrl: "/api/workspaces/{{params.id}}/billing-info",
});
```

**After an action.** Once something on the page changes the record, the blocks read their data again in place — no remount, the values stay on screen until the new ones land. A page header button does it on its own once it changed something (an `api` call that is not a `GET`, a form it opened that saved). A form names the built-in watch function, and a frontend component of your own calls `refreshPageBlocks()` ([Component events](/docs/extending-the-dashboard/component-events#refreshing-the-blocks-of-a-page)):

```ts
static suspend = Form({ kind: "action", submitUrl: "/api/workspaces/{{params.id}}/suspend", fields })
  .watch(FormEvents.SUBMIT_SUCCESS, BlockFunctions.REFRESH_PAGE);
```

```ts
@Get("billing-stats")
stats() {
  return {
    items: [
      { icon: "i-ph-receipt", eyebrow: "Invoices sent", value: 1284 },
      { icon: "i-ph-warning-octagon", tone: "error", eyebrow: "Overdue", value: 6,
        detail: "Oldest 41 days", detailTone: "error" },
    ],
  };
}
```

## StatGroup

**What it renders.** A row of headline figures, each a cell with an icon well, a mono label, the value and a detail line. `joined` draws one card split by hairlines (the security status strip); `cards` draws one compact stat card per figure (the modules summary). A cell with `to` links to where the figure is managed. Columns drop on narrow screens: a joined group goes to one column on phones, the compact cards keep two.

A `cards` cell is the same compact card as `KpiCard({ variant: "stat" })`. Use a [KPI card](/docs/components/charts-and-widgets) for one metric followed over a period, with its variation and sparkline; use a `StatGroup` for several figures or states read at a glance.

```ts
static status = StatGroup({
  layout: "joined",
  items: [
    { icon: "i-ph-shield-check", tone: "success", eyebrow: "Two-factor",
      value: "On", detail: "Authenticator app", to: "/settings/user/security" },
    { icon: "i-ph-devices", eyebrow: "Sessions", value: "3 active",
      detail: "This device + 2 others" },
  ],
});
```

| Option    | Type                  | Default     | Purpose                                    |
| --------- | --------------------- | ----------- | ------------------------------------------ |
| `items`   | `StatGroupItem[]`     | —           | The cells, in order.                       |
| `layout`  | `"joined" \| "cards"` | `joined`    | One card split in cells, or one card each. |
| `columns` | `number` (1–6)        | items count | Columns on wide screens.                   |
| `label`   | `string`              | —           | Accessible name of the group.              |

A `StatGroupItem` carries `eyebrow` and `value` (a number is formatted for the locale), plus optional `icon`, `tone` (well tone; `muted` by default when joined, `primary` as cards), `detail`, `detailTone` and `to`.

## KeyValueList

**What it renders.** Label / value rows split by hairlines, the label on the left and the value right-aligned, each value drawn by its `type`: `text`, `status` (a tinted pill), `money` (a currency amount), `date` (a localized date), `link` (an accent link) or `mono` (an identifier). A `detail` adds a dim note after the value. The list sits in a card by default, with `title` as the card's eyebrow; turn `card` off to place it inside a [Card](#card).

```ts
static subscription = KeyValueList({
  title: "Subscription",
  items: [
    { label: "Plan", value: "Business" },
    { label: "Status", value: "Past due", type: "status", tone: "error" },
    { label: "Next invoice", value: 588, type: "money", detail: "Oct 31" },
    { label: "Customer ID", value: "cus_Q8f2LmXv01", type: "mono" },
  ],
});
```

| Option     | Type                 | Default | Purpose                                  |
| ---------- | -------------------- | ------- | ---------------------------------------- |
| `items`    | `KeyValueListItem[]` | —       | The rows, in order.                      |
| `title`    | `string`             | —       | Eyebrow title of the card.               |
| `card`     | `boolean`            | `true`  | Card surface around the list.            |
| `dense`    | `boolean`            | `false` | Tighter rows, for side panels.           |
| `columns`  | `number` (1–3)       | `1`     | Columns on wide screens.                 |
| `currency` | `string`             | `EUR`   | Default ISO 4217 code of `money` values. |

A `KeyValueListItem` carries a `label` and a `value` (an ISO date for `date`, a number for `money`; an empty value shows a dash), plus optional `type`, `tone` (text colour, or the pill tone of a `status`), `to`, `detail` and `currency`.

## NavCardGrid

**What it renders.** A grid of navigation cards: an icon well, the title with an arrow that slides in on hover, a description, and optionally the target's live `state` in mono, a small uppercase `tag` after the title (the module a page comes from) and mono `readout` lines. An optional `title` and `description` head the grid.

```ts
static workspace = NavCardGrid({
  title: "Workspace",
  items: [
    { icon: "i-ph-users", title: "Members", to: "/settings/workspace/members",
      description: "People with access and pending invitations.",
      state: "8 of 10 seats used" },
    { icon: "i-ph-credit-card", title: "Billing", to: "/billing",
      state: "Payment failed", stateTone: "error", tag: "SaaS" },
  ],
});
```

| Option        | Type            | Default | Purpose                       |
| ------------- | --------------- | ------- | ----------------------------- |
| `items`       | `NavCardItem[]` | —       | The cards, in order.          |
| `columns`     | `number` (1–4)  | `3`     | Columns on wide screens.      |
| `title`       | `string`        | —       | Section title above the grid. |
| `description` | `string`        | —       | Line under the section title. |

A `NavCardItem` carries `title`, `icon` and `to`, plus optional `description`, `iconTone`, `state`, `stateTone`, `tag` and `readout`.

Given a `category` in place of `items`, the grid holds a card per page of it the viewer can open, in menu order. Each card carries the badge its navigation entry shows, in the card's top corner and drawn as the settings navigation draws it: in the badge's tone, neutral grey without one, and hidden at zero. A viewer who can open none of the pages gets no grid, title included, unless `empty` says what to show instead.

The cards are items of one block rather than blocks of their own: a grid of nav cards is one list, configured in one place, reflowed as one grid, and — with `fetchUrl` — fed by one route that computes every card's state. A single card is a one-item grid.

## EmptyState

**What it renders.** An icon well, a title, a short explanation and the link buttons that fit the case, centred. The `variant` says why it is empty and sets the icon, the tone and how it is announced (`error` as an alert, the others as a status). In a card by default.

```ts
static noInvoices = EmptyState({
  title: "No invoices yet",
  description: "Invoices appear here once a customer is billed.",
  actions: [{ label: "Create an invoice", to: "/invoices/new", icon: "i-ph-plus" }],
});
```

| Option        | Type                                                 | Default   | Purpose                                |
| ------------- | ---------------------------------------------------- | --------- | -------------------------------------- |
| `title`       | `string`                                             | —         | Title.                                 |
| `description` | `string`                                             | —         | Short explanation.                     |
| `variant`     | `"no-data" \| "no-result" \| "no-access" \| "error"` | `no-data` | Why it is empty.                       |
| `icon`        | `string`                                             | variant's | Overrides the icon.                    |
| `tone`        | tone                                                 | variant's | Overrides the well tone.               |
| `size`        | `"sm" \| "md" \| "lg"`                               | `md`      | `sm` compact, `lg` with a larger well. |
| `hatched`     | `boolean`                                            | `false`   | Hatched panel behind it.               |
| `actions`     | `BlockLinkAction[]`                                  | —         | Link buttons; the first one leads.     |
| `card`        | `boolean`                                            | `true`    | Card surface around it.                |

A `BlockLinkAction` is `{ label, to, icon?, variant?, color? }`. The block picks each button's look from its place; `variant` (`solid`, `outline`, `soft`, `subtle`, `ghost`, `link`) and `color` (a tone) override it.

## Banner

**What it renders.** A notice: a tinted wash fading from the left, a boxed icon in the tone, the title and a line of explanation, link buttons on the right (the last one is the main action) and an optional close button. `size: "sm"` is the compact one-line banner for cards and side panels.

A dismissed banner stays dismissed: the dismissal is kept in a cookie for a year, so the server render already leaves it out. It is remembered under `dismissKey`, or the block's id on its page without one (`welcome` for `.child("welcome", Banner(…))`), which holds when blocks are added or moved; change the key to show the banner again (a new beta, a new notice).

This is a block placed on one page. For a strip shown under the dashboard header on every page, use `RegisterLayoutBanner` ([Dashboard chrome](/docs/extending-the-dashboard/dashboard-chrome)).

```ts
static beta = Banner({
  tone: "warning",
  title: "Sales analytics is in beta",
  description: "Numbers refresh every 15 minutes.",
  actions: [{ label: "Send feedback", to: "#feedback" }],
  dismissible: true,
  dismissKey: "sales-beta-2026",
});
```

| Option        | Type                                                       | Default  | Purpose                                     |
| ------------- | ---------------------------------------------------------- | -------- | ------------------------------------------- |
| `title`       | `string`                                                   | —        | Title.                                      |
| `description` | `string`                                                   | —        | Line of explanation.                        |
| `tone`        | `"info" \| "success" \| "warning" \| "error" \| "primary"` | `info`   | Colour of the wash and the icon.            |
| `icon`        | `string`                                                   | tone's   | Overrides the icon.                         |
| `size`        | `"md" \| "sm"`                                             | `md`     | `sm` is the compact one-line banner.        |
| `actions`     | `BlockLinkAction[]`                                        | —        | Link buttons on the right.                  |
| `dismissible` | `boolean`                                                  | `false`  | Adds a close button; the dismissal is kept. |
| `dismissKey`  | `string`                                                   | block id | Key the dismissal is kept under.            |

## Card

**What it renders.** A titled card holding other blocks: the head with the eyebrow `title`, a mono `count`, a dim `description` line and link buttons on the right; the body, where the children stack; and an optional muted foot band.

`Card` is a container. Children added with `.child()` and no slot stack in the body. A child added with `{ slot: "actions" }` joins the head's link buttons, one with `{ slot: "footer" }` fills the foot band; each of those two slots holds one child, so several go in an `HStack`.

```ts
static connectors = Card({
  title: "Connectors",
  count: 4,
  padded: false,
  actions: [{ label: "View all", to: "/integrations", icon: "i-ph-arrow-right" }],
  footer: "Last sync 10:15",
})
  .child("list", KeyValueList({ card: false, dense: true, items: [/* … */] }));
```

| Option        | Type                      | Default   | Purpose                                               |
| ------------- | ------------------------- | --------- | ----------------------------------------------------- |
| `title`       | `string`                  | —         | Eyebrow title of the head.                            |
| `count`       | `number \| string`        | —         | Mono count after the title.                           |
| `description` | `string`                  | —         | Dim line under the title.                             |
| `actions`     | `BlockLinkAction[]`       | —         | Link buttons on the right of the head.                |
| `footer`      | `string`                  | —         | Muted text in the foot band.                          |
| `padded`      | `boolean`                 | `true`    | Body padding; off for a list or a table edge to edge. |
| `variant`     | `"default" \| "elevated"` | `default` | `elevated`: stronger shadow on an empty backdrop.     |

## Permissions

These blocks hold no data of their own beyond their options; a block with a `fetchUrl` reads it with the viewer's session, so the route applies its own checks. Like every block, each one is a position in the page layout that a role must be granted to see ([Auth & permissions](/docs/auth-and-tenancy/auth-and-permissions)), and a `Card`'s children each carry their own position under it.
