Pick the path that matches what you want to do first:

**Start a project.** Your own back office, with the DMS and the AI assistant, and no sample data. This page walks through it.

```bash [Terminal]
npx @antelopejs/core project init my-project --template dms-starter
```

**Try the full demo.** Helio, the back office of a fictional solar installer, with every DMS module. The [Tutorial](/docs/getting-started/tutorial) builds on it.

```bash [Terminal]
npx @antelopejs/core project init dms-demo --template dms-demo
```

**Try it on an existing database.** The DMS next to a sample PostgreSQL, MongoDB or RethinkDB database, to try Connect. [Connect an existing database](/docs/external-database) walks through it.

```bash [Terminal]
npx @antelopejs/core project init dms-connect-demo --template dms-connect-demo
```

Already have an app? To run the DMS inside AdonisJS, use `--template dms-adonis` and follow [Run the DMS inside AdonisJS](/docs/getting-started/adonisjs).

In the rest of this page, we start a project from the [`template-dms`](https://github.com/AntelopeJS/template-dms) template. At the end, you have a running dashboard, your own administrator account, and first pages that the assistant generated from your database, as TypeScript in your repository.

## Before you start

You need git, Node.js to run the AntelopeJS CLI, and Docker with Compose v2. Docker runs the DMS and the MongoDB that holds its own data. To keep that data in MySQL or MariaDB instead, load `@antelopejs/mysql` as the database module, as [Installation](/docs/getting-started/installation#start-a-database) shows. To run the DMS without Docker, follow the [template README](https://github.com/AntelopeJS/template-dms#run-without-docker) instead.

## Create the project

Create a project from the **DMS Starter** template with the AntelopeJS CLI, then start it:

```bash [Terminal]
npx @antelopejs/core project init my-project --template dms-starter
cd my-project
docker compose up
```

The CLI asks you to confirm the project name and whether to create a git repository. Add `--yes` to `project init` to accept its defaults without a prompt. The first start installs every module, so it takes a few minutes. The dashboard is ready when the log prints `Local: http://localhost:3001/`.

## Create your administrator

A fresh database has no account, and there are no default credentials. The `dms` log prints `No owner exists yet`, followed by an address such as `http://localhost:3001/onboarding?token=…`. Open that address. It carries the setup token, which proves that you deployed this instance, and the wizard reads it from there.

1. Enter a platform name, then select **Continue to administrator**.
2. Enter your name, your email, and a password. The password needs at least 8 characters, with an uppercase letter, a digit, and one of `@$!%*?&`. Other special characters, such as `#` or `-`, are refused. If you opened `http://localhost:3001` without the token, this step also asks for the **Setup token** from the log line.
3. Select **Create administrator account**, then **Open the dashboard**.

The dashboard opens on the template's **Home** page. From now on, the sign-in page is `/auth`.

## Connect the assistant

The template ships [`@antelopejs/dms-assistant`](/docs/modules/assistant/introduction). Its popup opens over the dashboard the first time, and on each start until the setup is done. Select **Get started**, then pick the AI you use. It runs on your own Claude or ChatGPT subscription.

- **Claude.** The popup shows `claude setup-token`. Run it in a terminal on your machine, and paste the token it prints. The popup checks it with Anthropic, then saves it on the machine that runs the DMS.
- **Codex.** Select **Continue with ChatGPT** and approve the request. The DMS runs in a container, so the page ChatGPT sends you back to does not load. Select **DMS running on another machine?**, copy that page's full address, and paste it.

Select **Skip for now** to set it up later. The **Assistant** chip at the bottom left of the dashboard opens the popup again.

## Connect your database

Once the AI is connected, choose a starting point. Select **Start from an existing database**, pick its engine, and paste a connection URL. The DMS runs in a container, so use `host.docker.internal` as the host of a database on your machine, as in `postgres://reader:secret@host.docker.internal:5432/shop`. An account that can only read is enough.

Select **Connect and analyse**. The popup checks the server, the sign-in and the read access, saves the URL in the project's `.env`, then reads the schema. It lists the tables and the screens it proposes. Choose **Generate a first mockup** to shape the pages with the assistant first, or **Build directly** to generate them now.

[Connect an existing database](/docs/external-database) covers the mapping in detail, with statistics, relations and the questions.

## Start from a description

Without a database, select **Start from scratch** and describe your product in a few sentences. The assistant asks what it needs, then draws a mockup. Comment on it, and the assistant builds the pages it shows as TypeScript in this repository, so you can review it, edit it and commit it. [Mockups](/docs/ai-and-claude-code/mockups) explains the flow.

Open the assistant's chat with the sparkle button at the top right, or press `Ctrl` `Shift` `K`. Ask it for a page, a dashboard or a fix.

## Stop and start over

Press `Ctrl` `C` to stop the project. Your data stays in Docker volumes. `docker compose down -v` removes them, and the next start asks for a new administrator.
