Pick the path that matches what you want to do first:

**Start a project.** Your own back office, with the DMS, the Builder and the AI assistant, and no sample data. This page walks through it.

```bash [Terminal]
npx @antelopejs/core project init my-project --template dms-starter
```

**Try the full demo.** Helio, the back office of a fictional solar installer, with every DMS module. The [Tutorial](/docs/getting-started/tutorial) builds on it.

```bash [Terminal]
npx @antelopejs/core project init dms-demo --template dms-demo
```

**Try it on an existing database.** The DMS next to a sample PostgreSQL, MongoDB or RethinkDB database, to try Connect. [Connect an existing database](/docs/external-database) walks through it.

```bash [Terminal]
npx @antelopejs/core project init dms-connect-demo --template dms-connect-demo
```

Already have an app? To run the DMS inside AdonisJS, use `--template dms-adonis` and follow [Run the DMS inside AdonisJS](/docs/getting-started/adonisjs).

In the rest of this page, we start a project from the [`template-dms`](https://github.com/AntelopeJS/template-dms) template. At the end, you have a running dashboard, your own administrator account, and a first page that the Builder generated from your database, as TypeScript in your repository.

## Before you start

You need git, Node.js 24, and Docker with Compose v2. Docker runs the DMS and the MongoDB that holds its own data. To run the DMS without Docker, follow the [template README](https://github.com/AntelopeJS/template-dms#run-without-docker) instead.

## Create the project

Create a project from the **DMS Starter** template with the AntelopeJS CLI, then start it:

```bash [Terminal]
npx @antelopejs/core project init my-project --template dms-starter
cd my-project
docker compose up
```

The CLI asks whether to create a git repository. Add `--yes` to `project init` to accept its defaults without a prompt. The first start installs every module, so it takes a few minutes. The dashboard is ready when the log prints `Local: http://localhost:3001/`.

## Create your administrator

A fresh database has no account, and there are no default credentials. The `dms` log prints `No owner exists yet`, followed by an address such as `http://localhost:3001/onboarding?token=…`. Open that address. It carries the setup token, which proves that you deployed this instance, and the wizard reads it from there.

1. Enter a platform name, then select **Continue to administrator**.
2. Enter your name, your email, and a password. The password needs at least 8 characters, with an uppercase letter, a digit, and one of `@$!%*?&`. Other special characters, such as `#` or `-`, are refused. If you opened `http://localhost:3001` without the token, this step also asks for the **Setup token** from the log line.
3. Select **Create administrator account**, then **Open the dashboard**.

The dashboard opens on the template's **Home** page. From now on, the sign-in page is `/auth`.

## Connect your database

Open the Builder with the hammer button at the top right of any page, or press `Ctrl` `B` (`⌘` `B` on macOS). Choose the **Database** tab, then **Connect a database**.

1. Enter a **Name**, such as `shop`, and pick the **Database type**: PostgreSQL, MongoDB or RethinkDB.
2. Paste a connection URL into **Connection** and press **Fill in**. The DMS runs in a container, so use `host.docker.internal` as the host of a database on your machine, as in `postgres://reader:secret@host.docker.internal:5432/shop`. An account that can only read is enough.
3. Press **Connect**. The Builder adds the connection to `antelope.config.ts`, writes the URL into `.env`, reloads the project, then reads the database's schema. It reads no row.

When it finishes, the Builder lists the tables it suggests as pages and the questions left. Choose **Review it myself**, then **Apply** and **Confirm**. Each mapped table gets a read-only page in the sidebar, under a section named after the connection. Its code is in `modules/builder-db-shop-tables/`.

[Connect an existing database](/docs/external-database) covers the mapping in detail, with statistics, relations and the questions.

## Build a page with the Builder

Choose the **Page** tab of the Builder to edit the open page. Drag a block from the palette onto the page, set it up in its settings panel, and press **Save**. The Builder writes what you build as TypeScript in this repository, so you can review it, edit it and commit it. [Page editor](/docs/modules/builder/usage/page-editor) explains each part.

## Use the AI assistant

Open the assistant with the sparkle button at the top right, or press `Ctrl` `Shift` `K`. It runs a coding agent, Claude Code or Codex, in the project's folder, on your own subscription. Ask it for a page, a dashboard or a fix. In the Database workspace, **Let the assistant finish** hands it the mapping of a new connection.

The container has none of your logins, so the assistant answers `Not logged in` until you give it one. Run `claude setup-token` on your machine, put the token in a `.env` file next to `compose.yaml` as `CLAUDE_CODE_OAUTH_TOKEN=…`, then run `docker compose up` again. An Anthropic API key works the same way as `ANTHROPIC_API_KEY`. To use Codex, open **Assistant** > **Settings** and press **Sign in with ChatGPT**. The [template README](https://github.com/AntelopeJS/template-dms#ai-assistant) details each option.

## Stop and start over

Press `Ctrl` `C` to stop the project. Your data stays in Docker volumes. `docker compose down -v` removes them, and the next start asks for a new administrator.
