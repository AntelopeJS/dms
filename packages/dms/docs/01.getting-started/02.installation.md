For a new application, follow [Start your project](/docs/getting-started/quickstart) instead. The starter template it uses already declares the backend and frontend packages and runs them in Docker. This page is for adding the DMS to an existing AntelopeJS project.

::tip
If you build with Claude Code or Codex, install the `antelopejs` plugin once. Your project's packages then bring their own skills. See [Install the plugin](/docs/ai-and-claude-code/install) and the [skill catalog](/docs/ai-and-claude-code/skill-catalog).
::

## What you need

| Tool | Role |
| --- | --- |
| **Node.js** | Runs the backend and the frontend build. The demo template pins its release in `.nvmrc`. |
| **pnpm** | Installs the project and its modules. The demo template pins its release in the `packageManager` field of `package.json`. |
| **`ajs` CLI** | The AntelopeJS CLI. It runs your backend project. |
| **A database module** | Any module that implements the `interface-database` contract stores the DMS models. The demo uses `@antelopejs/mongodb`. |
| **Redis** | Realtime messages and caching across several backend instances. A single development instance runs without it. |
| **`ajs dms` CLI** | The DMS frontend loader. It serves the dashboard. |

The `@antelopejs/*` ranges a DMS release supports are in the compatibility block of the [`dms` README](https://github.com/AntelopeJS/dms/tree/main/packages/dms#compatibility).

:::steps{level="3"}

### Install the ajs CLI

Add `@antelopejs/core` to the project and run its local binary:

```bash [Terminal]
pnpm add -D @antelopejs/core
pnpm exec ajs --help
```

The AntelopeJS documentation covers how `ajs` creates, runs, and watches projects.

### Start a database

The DMS stores its models through a database module. With Docker, this local-only `docker-compose.yml` starts MongoDB and Redis on the addresses the docs' `antelope.config.ts` examples use (`mongodb://127.0.0.1:27017` and `redis://localhost:6379`):

```yaml [docker-compose.yml]
services:
  mongo:
    image: mongo:8
    ports:
      - "127.0.0.1:27017:27017"
  redis:
    image: redis:7
    ports:
      - "127.0.0.1:6379:6379"
```

```bash [Terminal]
docker compose up -d
```

Leave out the `redis` service if one backend instance is enough. Any other MongoDB install works too. Set its address in the `@antelopejs/mongodb` configuration of `antelope.config.ts`.

### Add the DMS module

Add the module to `antelope.config.ts`:

```bash [Terminal]
pnpm exec ajs project modules add @antelopejs/dms
```

The DMS also needs an API module, a database module, and an authentication module. [Project setup](/docs/building/project-setup) shows a complete `antelope.config.ts`.

### Add the `ajs dms` frontend loader

The `@antelopejs/dms-frontend` package ships the frontend loader, whose binary is `ajs dms`. Add it as a development dependency:

```bash [Terminal]
pnpm add -D @antelopejs/dms-frontend
pnpm exec ajs dms --help
```

Then add a script that starts the dashboard:

```json [package.json]
{
  "scripts": {
    "frontend:dev": "ajs dms dev"
  }
}
```

The [Frontend](/docs/frontend/cli/overview) section documents every command and flag of `ajs dms`.

:::

## Add optional dependencies

Two features need a module the base stack does not include. Add each one when you reach the feature:

| Dependency | Needed for | Docs |
| --- | --- | --- |
| A module that implements `interface-email`, such as `@antelopejs/nodemailer` with `ethereal: true` in development | Invitations, email validation, two-factor codes, and password resets | [Backend services](/docs/building/backend-services) |
| A module that implements `interface-file-storage` | The `file` and `image` field types. Do not use local-disk storage in production. | [File storage](/docs/components/file-storage) |
