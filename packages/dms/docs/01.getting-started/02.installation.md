# Installation

The DMS runs on the AntelopeJS toolchain and a database. For a new application, use the [template-based quickstart](/docs/getting-started/quickstart): it already declares the backend and frontend dependencies. The manual CLI installation below is for integrating an existing project.

## What you need

| Tool                                    | Version | Role                                                                                     |
| --------------------------------------- | ------- | ---------------------------------------------------------------------------------------- |
| **Node.js**                             | 22 LTS  | Runs the backend and the frontend build.                                                 |
| **pnpm**                                | 10.2.0  | Matches the demo template's package manager.                                             |
| [**`ajs` CLI**]{.whitespace-nowrap}     | latest  | The AntelopeJS CLI — runs your backend project.                                          |
| **Database**                            | —       | Any module implementing the `interface-database` contract backs the DMS models.          |
| **Redis**                               | 7.x     | Realtime pub/sub and caching. Optional on a single dev instance, recommended everywhere. |
| **Docker**                              | —       | Runs the database and Redis in development. Any install works; Docker is the quickest.   |
| [**`ajs dms` CLI**]{.whitespace-nowrap} | latest  | The DMS frontend loader — serves the dashboard.                                          |

:::steps{level="3"}

### Install Node.js and the ajs CLI

Install Node 22 LTS with your usual method. The demo provides a local `ajs` binary through `pnpm exec`; for an existing project that needs the CLI, install it locally:

```bash [Terminal]
pnpm add -D @antelopejs/core
pnpm exec ajs --help
```

`ajs` is pure AntelopeJS — scaffolding, running, and watching projects are covered by the AntelopeJS documentation, not here.

### Start a database and Redis

The DMS models run on a database module implementing the AntelopeJS `interface-database` contract. The demo uses MongoDB 8; Redis is optional on one development instance. If you use Docker, create this local-only configuration:

```yaml [docker-compose.yml]
services:
  mongo:
    image: mongo:8
    ports:
      - "127.0.0.1:27017:27017"
  redis:
    image: redis:7
    ports:
      - "127.0.0.1:6379:6379"
```

```bash [Terminal]
docker compose up -d
```

The connection URLs these expose (`mongodb://127.0.0.1:27017`, `redis://localhost:6379`) are the defaults used throughout the docs' `antelope.config.ts` examples. Many projects fold this into their dev script: `docker compose up -d && ajs project dev -w`.

### Get the `ajs dms` frontend loader

The Vue dashboard frontend is served by the loader shipped by the **`@antelopejs/dms-frontend`** package, whose CLI binary is `ajs dms`. The demo already includes it. For an existing project, add it as a dev dependency and invoke its local binary with pnpm:

```bash [Terminal]
pnpm add -D @antelopejs/dms-frontend
pnpm exec ajs dms --help
```

```jsonc [package.json — the conventional script]
"scripts": {
  "frontend:dev": "ajs dms dev"
}
```

The CLI's commands and flags (`dev`, `build`, `start`, `prepare`, `clean`) are documented in [Frontend CLI](/docs/building/frontend-cli).

:::

## Optional dependencies

Two features rely on modules the base stack does not include. Install each when you reach the feature — the docs flag the dependency where it applies:

| Dependency                                                                                           | Needed for                                            | Doc                                                                       |
| ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------- |
| An `interface-email` implementation — `@antelopejs/nodemailer` (`ethereal: true` in dev)             | Invites, email validation, 2FA codes, password resets | [Backend services](/docs/building/backend-services#html--email-rendering) |
| A module implementing the `interface-file-storage` contract (avoid local-disk storage in production) | The `file`/`image` field types                        | [File storage](/docs/components/file-storage)                             |
