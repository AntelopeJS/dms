# Overview

When your frontend layer ships its own Vue ([Frontend layer](/docs/building/frontend-layer)), these are the composables it calls to talk to the DMS — the [table below](#the-toolkit) maps them to their chapters. Where the previous section, [Extending the dashboard](/docs/extending-the-dashboard/overview), is about _registering_ capabilities, this one is the _toolkit_ your components consume.

All are auto-imported by the base layers — call them from `<script setup>` or a composable; no import needed.

## The toolkit

| Chapter                                                                           | Composables                                                                                             |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| [Auth requests & permissions](/docs/frontend-composables/authenticated-requests)  | `useApiData`, `useAuthFetch` (`$authFetch`), `usePermissions`, `useMultiAccount`, `useCurrentUser`, `useLogout`, `useSessionRecovery` |
| [Realtime & notifications](/docs/frontend-composables/realtime-and-notifications) | `useRealtimeTopic`, `usePageRealtime`, `usePageLive`, `usePageLiveRefresh`, `useUserRealtime`, `useNotifications`             |
| [Page context](/docs/frontend-composables/page-context)                           | `useSiteLayout`, `useCurrentModule`, `useIsOwner`, `usePageRecordLabel`, `usePageToolbarSize`, `useDevReload`, `usePreferences`, `useFavoritePages`, page setup, …  |
| [UI toolkit](/docs/frontend-composables/ui-toolkit)                               | `useModal`, `useDrawer`, `useConfirm`, `useConfirmFrom`, `useApiErrorPresenter`, `useExportJob`                  |
| [Utilities](/docs/frontend-composables/utilities)                                 | i18n (`useTranslation`), leave guard (`usePageLeaveGuard`), onboarding                                  |

::warning
To read backend data a component renders, use **`useApiData`**; for any other backend call (a write, a read on a click), **`$authFetch`** from `useAuthFetch` — never a bare `$fetch`. Only these attach the session and recover from an expired one, and only `useApiData` renders the data on the server and hands it to the browser. See [Auth requests & permissions](/docs/frontend-composables/authenticated-requests).
::
