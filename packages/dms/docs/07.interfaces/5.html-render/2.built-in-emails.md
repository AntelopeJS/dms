# Built-in Emails

## Overview

The DMS sends seven emails of its own. Each one is a template registered through [`RegisterHtmlTemplate`](./1.introduction.md#registerhtmltemplate), rendered by the frontend server from a Vue component in `frontend-vue/layers/dms-layout/app/emails/`, and delivered through `@antelopejs/interface-email`. They share one frame, `EmailLayout`: the branding logo, a white card, a heading, the body, a separator and a footer.

| Template | Sent when | Sent to | Subject |
| -------- | --------- | ------- | ------- |
| `EmailUserValidation` | A user signs up while `auth.mustValidateEmail` is on, or asks for a new code | The new account's address | `Verify Your Email` |
| `EmailResetPassword` | A user asks for a password reset | The account's address | `Reset Your Password` |
| `EmailTwoFactor` | A user signs in with email as their second factor | The account's address | `Your verification code` |
| `EmailAdminInvite` | A member is invited to the platform or to a workspace | The invited address | `You're invited to join <workspace> on <platform>`, shorter when a name is unknown |
| `EmailChangeVerification` | A user asks to change their sign-in email | The new address | `Confirm your new sign-in email` |
| `EmailChangeNotice` | The same request | The current address | `Your sign-in email is being changed` |
| `EmailExportReady` | A data export delivered by email has finished | The user who asked for it | `Your data export is ready` |

These names are taken: a module registering its own template under one of them replaces the DMS's entry in the registry. Pick other names for your own emails.

## Props

What the backend passes to each template. A template that replaces a built-in one receives the same props.

| Template | Props |
| -------- | ----- |
| `EmailUserValidation` | `userName`, `validationCode`, `expiresIn` (for example `24 hours`, from `auth.emailValidationTokenLifetime`) |
| `EmailResetPassword` | `userName`, `resetCode`, `expiresIn` (from `auth.passwordRecoverTokenLifetime`) |
| `EmailTwoFactor` | `userName`, `verificationCode` |
| `EmailAdminInvite` | `email`, `signupLink`, `expiresInDays`, and when known `workspaceName`, `inviterName`, `platformName` (`meta.title`) |
| `EmailChangeVerification` | `userName`, `newEmail`, `code`, `expiresIn` (from `auth.emailValidationTokenLifetime`) |
| `EmailChangeNotice` | `userName`, `newEmail` |
| `EmailExportReady` | `userName`, `downloadLink`, `expiresIn`, `partial`, `failedSources` (the export sources that could not be included) |

`userName` is the user's name, or their email address when they have none.

## Language

`EmailAdminInvite` is written in the invitee's language, English or French, subject included: its text lives under the `emails.admin_invite` keys of the `dms-layout` locale files, which a module's own locale files can override. The other six emails are in English.

## Logo

Every built-in email draws `branding.logo.default.light` from the email `appConfig` (see [Email Layout](./1.introduction.md#email-layout)) with `publicLogoOnly` on. The logo shows only when a mail client can load it: a PNG or JPEG served from a public `http(s)` address. The default DMS logo is an SVG, which Gmail and Outlook refuse, so out of the box the emails carry no logo. To show yours, export an `appConfig` with a PNG logo from your module's `dms.email.ts`, and serve the dashboard from a public `clientBaseUrl`:

```ts [frontend-vue/dms.email.ts]
export const appConfig = {
  branding: { logo: { default: { light: "/images/acme-logo.png" } } },
};

export const serverEmailTemplates = import.meta.glob("./app/emails/**/*.vue");
```

Email configurations merge in module priority order, so a module registered with a priority above the DMS's (`0`) wins.
