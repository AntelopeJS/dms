The 0.14 release line corrects published types that said something the DMS does not do. The [interface upgrade notes](https://github.com/AntelopeJS/dms/blob/main/packages/interface-dms/UPGRADING.md) list each one with the TypeScript error a module gets. The DMS release that implements it removes the Cascader props the picker never read. HTTP routes and their answers are unchanged.

## Checklist

| Area | What to do | Section |
| --- | --- | --- |
| Dependencies | Move the `@antelopejs/interface-dms` dependency in `package.json` to the 0.14 release line | [Dependencies](#dependencies) |
| Export jobs | Pass `contextSchema` with `isOwnedBy`, and check `context` in `generate` | [Export jobs](#an-export-ownership-check-reads-its-context-through-a-schema) |
| Cascader | Stop passing `initialValue`, `fallback`, `loading`, `componentId`, `pageId` and `routeParams` to `DmsCascader` | [Cascader](#the-cascader-takes-only-the-props-it-reads) |

## Dependencies

Move `@antelopejs/interface-dms` in the module's `package.json` `dependencies` to the 0.14 release line.

## An export ownership check reads its context through a schema

An `isOwnedBy` passed to `getExportJobStatus` or `downloadExportJob` comes with the zod schema the job's stored `context` is read back through. A stored context the schema refuses answers 403 without calling `isOwnedBy`:

```ts fragment
// Before
getExportJobStatus<{ year: number }>(ctx, user, jobId, {
  isOwnedBy: (_record, context) => context.year === 2026,
});
// After
getExportJobStatus(ctx, user, jobId, {
  contextSchema: z.object({ year: z.number() }),
  isOwnedBy: (_record, context) => context.year === 2026,
});
```

`generate` receives `context` as `TContext | undefined`: a job started without one hands it `undefined`.

## The Cascader takes only the props it reads

`DmsCascader`, the picker behind `FormComponents.InputCascader`, no longer declares `initialValue`, `fallback`, `loading`, `componentId`, `pageId` and `routeParams`. It never read them. A form field renders it as before. A page that still passes one gets the same picker, and Vue puts the value on the picker's root element as an HTML attribute, as it does for the other field components that do not declare it. Delete them:

```vue fragment
<!-- Before -->
<DmsCascader
  search-url="/api/categories/select"
  :key-mapping="keys"
  :page-id="pageId"
  fallback="No category"
/>
<!-- After -->
<DmsCascader search-url="/api/categories/select" :key-mapping="keys" />
```
