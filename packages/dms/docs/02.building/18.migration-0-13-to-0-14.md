The 0.14 release line corrects published types that said something the DMS does not do. The [interface upgrade notes](https://github.com/AntelopeJS/dms/blob/main/packages/interface-dms/UPGRADING.md) list each one with the TypeScript error a module gets. The DMS release that implements it removes the Cascader props the picker never read, and gives every DMS Vue component a name of two words or more, so the registered names change. HTTP routes and their answers are unchanged. A module that only calls the `@antelopejs/interface-dms/base` builders (`Grid`, `Tab`, `Form`, `InputSelect` and the others) changes nothing for the renames but its dependency: the builders send the new names.

## Checklist

| Area | What to do | Section |
| --- | --- | --- |
| Dependencies | Move the `@antelopejs/interface-dms` dependency in `package.json` to the 0.14 release line | [Dependencies](#dependencies) |
| Export jobs | Pass `contextSchema` with `isOwnedBy`, and check `context` in `generate` | [Export jobs](#an-export-ownership-check-reads-its-context-through-a-schema) |
| Cascader | Stop passing `initialValue`, `fallback`, `loading`, `componentId`, `pageId` and `routeParams` to `DmsInputCascader` | [Cascader](#the-cascader-takes-only-the-props-it-reads) |
| Backend strings | Replace each old kebab name in `CustomComponent`, `ComponentBuilder`, `componentName` and an input declaration with its new name | [Backend strings](#backend-strings) |
| Frontend modules | Rename `<DmsCard>`, `resolveComponent("DmsCard")` and every other use of an old `Dms` name | [Frontend modules](#frontend-modules) |

| Layer imports | Import the seven renamed `entries/components` files by their new names | [Layer imports](#layer-imports) |

## Dependencies

Move `@antelopejs/interface-dms` in the module's `package.json` `dependencies` to the 0.14 release line.

## An export ownership check reads its context through a schema

An `isOwnedBy` passed to `getExportJobStatus` or `downloadExportJob` comes with the zod schema the job's stored `context` is read back through. A stored context the schema refuses answers 403 without calling `isOwnedBy`:

```ts fragment
// Before
getExportJobStatus<{ year: number }>(ctx, user, jobId, {
  isOwnedBy: (_record, context) => context.year === 2026,
});
// After
getExportJobStatus(ctx, user, jobId, {
  contextSchema: z.object({ year: z.number() }),
  isOwnedBy: (_record, context) => context.year === 2026,
});
```

`generate` receives `context` as `TContext | undefined`: a job started without one hands it `undefined`.

## The Cascader takes only the props it reads

`DmsInputCascader` (registered as `DmsCascader` before this release, see [Renamed components](#renamed-components)), the picker behind `FormComponents.InputCascader`, no longer declares `initialValue`, `fallback`, `loading`, `componentId`, `pageId` and `routeParams`. It never read them. A form field renders it as before. A page that still passes one gets the same picker, and Vue puts the value on the picker's root element as an HTML attribute, as it does for the other field components that do not declare it. Delete them:

```vue fragment
<!-- Before -->
<DmsInputCascader
  search-url="/api/categories/select"
  :key-mapping="keys"
  :page-id="pageId"
  fallback="No category"
/>
<!-- After -->
<DmsInputCascader search-url="/api/categories/select" :key-mapping="keys" />
```

The `fallback` option goes with it. `CascaderRelationType` and `FormComponents.InputCascader` no longer accept `fallback`, which the picker never showed. A column or form that sets it stops compiling with TS2353. Delete the option.

Renaming the file renames the component, and the kebab form is the same name spelled the way a backend sends it ([Component naming](/docs/building/frontend-layer#component-naming)). ## Backend strings

Four kinds of backend code name a component by string, and each stops resolving with the old string:

- `CustomComponent("dms-chart")` and `new ComponentBuilder("dms-chart")`.
- A `componentName` compared or written by hand, as in a test or a page transform.
- An input declaration on a field type, such as `inputComponent: { componentName: "dms-select" }`.
- A module's own check on a serialized page, such as `node.componentName === "dms-form"`.

```ts fragment
// Before
static usage = CustomComponent("dms-grid").options({ gap: "1rem" });
// After
static usage = CustomComponent("dms-grid-block").options({ gap: "1rem" });
```

A builder emits the new string without a change in your code. `Grid({ gap: "1rem" })` sends `dms-grid-block` after the upgrade, and `InputSelect(...)` sends `dms-input-select`. A module that built every block with a builder has nothing to change.

## Frontend modules

A template or a render function that uses a DMS component by its old name no longer resolves to it.

```vue
<!-- Before -->
<DmsCard title="Usage">
  <DmsMeter :segments="segments" />
</DmsCard>
<!-- After -->
<DmsCardPanel title="Usage">
  <DmsMeterBar :segments="segments" />
</DmsCardPanel>
```

```ts fragment
// Before
const Wrapper = resolveComponent("DmsCard");
// After
const Wrapper = resolveComponent("DmsCardPanel");
```

A component that a module registers under its own prefix is unaffected: only the names in the table above change.

## Stored JSON

A mockup or a page draft saved before the upgrade can hold an old `componentName`, such as `"componentName": "dms-chart"`. Compiling it fails with `no registered block emits the component "dms-chart"`. Replace each old kebab name in the stored document with its new one from the table, then save it again. A node that carries a `type` (`Grid`, `Chart`, `Form`) and no `componentName` needs no change.

## Layer imports

The layers import each other through `entries/components` files named after the component they re-export. Seven of those files follow their component:

| Before | After |
| --- | --- |
| `entries/components/layout/Footer` | `entries/components/layout/LayoutFooter` |
| `entries/components/onboarding/steps/ready` | `entries/components/onboarding/steps/StepReady` |
| `entries/components/table/Actions` | `entries/components/table/TableActions` |
| `entries/components/table/Empty` | `entries/components/table/TableEmpty` |
| `entries/components/table/Pagination` | `entries/components/table/TablePagination` |
| `entries/components/table/Table` | `entries/components/table/TableRoot` |
| `entries/components/table/Views` | `entries/components/table/TableViews` |

A module that imports a layer file by path, for example `#dms-ui/app/entries/components/table/Table`, updates the path. The `#dms-*` aliases and every other entry file are unchanged.
