The DMS runs on `@antelopejs/interface-database` 0.4 and `@antelopejs/interface-database-decorators` 0.5.2. A query is no longer a promise: it runs only through `.run()`. A deployment needs a database module that implements 0.4, and a module that queries the database changes each query it awaits.

## Checklist

| Area | What to do | Section |
| --- | --- | --- |
| Database module | Load `@antelopejs/mongodb` 1.8.0, `@antelopejs/postgres` 0.4.0 or `@antelopejs/rethinkdb` 1.10.0 or later | [Database module](#database-module) |
| Dependencies | Move `interface-database` to 0.4 and `interface-database-decorators` to 0.5.2 | [Dependencies](#dependencies) |
| Queries | Call `.run()` on every query you await, return or pass to `Promise.all` | [Queries run through run](#queries-run-through-run) |
| `cast()` | Use the object `cast()` returns | [cast returns a new object](#cast-returns-a-new-object) |
| `Schema.get` | Drop its type arguments | [Schema.get takes no type arguments](#schemaget-takes-no-type-arguments) |
| Builder routes | Add `.run()` to a generated stats route that awaits a model call without it | [Generated routes](#generated-routes) |

## Database module

Interface 0.4 changes what a database module implements, so the DMS needs a release built on it. Load one of these or a later one:

| Database | Module | Release |
| --- | --- | --- |
| MongoDB | `@antelopejs/mongodb` | 1.8.0 or later |
| PostgreSQL | `@antelopejs/postgres` | 0.4.0 or later |
| RethinkDB | `@antelopejs/rethinkdb` | 1.10.0 or later |

The same applies to the module that holds the DMS's own data and to the one a Connect project reads an existing database through.

## Dependencies

Raise both ranges in the `package.json` of a module that queries the database, and keep them wide enough for every module of the project to resolve one copy of each package ([Architecture](/docs/getting-started/architecture)):

```json fragment
{
  "dependencies": {
    "@antelopejs/interface-database": ">=0.4.0 <1.0.0",
    "@antelopejs/interface-database-decorators": ">=0.5.2 <1.0.0"
  }
}
```

`@antelopejs/interface-dms` declares the same two ranges as peers.

## Queries run through run

A query only records what to run. `await` on a query without `.run()` resolves to the query itself and sends nothing to the database, so a missing `.run()` fails silently. This holds for a query you await, return from an `async` function, hand to `Promise.all` or `Promise.race`, or chain `.then` on:

```ts fragment
// Before
const rows = await GetModel(OrderModel).table.getAll(ids, "customerId");
const [orders, total] = await Promise.all([page, page.count()]);
await schema.createInstance(tenantId);
// After
const rows = await GetModel(OrderModel).table.getAll(ids, "customerId").run();
const [orders, total] = await Promise.all([page.run(), page.count().run()]);
await schema.createInstance(tenantId).run();
```

The model methods that `@antelopejs/interface-database-decorators` 0.5.2 provides, such as `get`, `getAll` and `insert`, already run their query and still return a promise.

## cast returns a new object

`cast()` records no stage and no longer changes the object it is called on. Use what it returns:

```ts fragment
// Before
row.key("params").cast<ParamValues>();
return row.key("params").values();
// After
return row.key("params").cast<ParamValues>().values();
```

## Schema.get takes no type arguments

`Schema.get(id)` returns `Schema<any, unknown> | undefined`. Take a type from the owner of the schema, such as the model or table class, or from `ReturnType<typeof Schema.get>`.

```ts fragment
// Before
const schema = Schema.get<MySchema>("my-schema");
// After
const schema = Schema.get("my-schema");
```

## Generated routes

The builder writes a stats route that awaits the model method, and now writes `await model.revenue().run()`. The builder still reads a route written without `.run()`, but that route answers with the query instead of the figures. Add `.run()` to the awaited call of each stats route you generated before.
