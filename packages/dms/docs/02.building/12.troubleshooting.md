The recurring failures of DMS development look alike from the outside: a blank pane, a 404, a stale screen. Their causes live in different parts of the stack. Each symptom below maps to its cause and to the section that explains it. The linked sections own the full story.

| Symptom                                                                            | Cause                                                                                                            | Explained in                                                                             |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| A custom component renders blank, no console error                                 | A name mismatch. The backend names the component differently from the name `sdk.registerComponent` gave it, and Vue stays silent | [Frontend layer](/docs/building/frontend-layer#component-naming)                         |
| A module's composable or util is not defined in the application                  | Auto-imports are opt-in. A module without `dms.frontend.build.ts` has nothing auto-imported, and `app/build/` is never auto-imported | [Frontend layer](/docs/building/frontend-layer#auto-imports) |
| A component renders blank, and the backend sends its name without the module's prefix | A module's `componentPrefix` is part of the registered name, and a leading `Dms` is kept. The backend sends `Table` where the registered name is `DmsTable` | [Frontend layer](/docs/building/frontend-layer#component-naming) |
| You edit layer code but the dashboard shows the old version                        | The dev server serves the materialized layer copy, and a watcher missed the edit                               | [Frontend layer](/docs/building/frontend-layer#the-materialized-workspace-is-a-physical-copy)  |
| Boot fails with `Unresolved interface dependencies: <module> requires <package>`   | A dependency is an interface package (an `antelopeJs` manifest whose `implements` is empty or names only itself) that no loaded module lists in `implements` | [Distributable module](/docs/building/distributable-module#the-module-manifest-antelopejs-in-packagejson) |
| The backend builds clean but the page 500s when opened                             | A Vue template or compile error in the layer. `tsc` never compiles the frontend module                               | [Frontend layer](/docs/building/frontend-layer)                                          |
| A link or `router.push` to a module page 404s                                      | The path omits the `/modules/<moduleId>` prefix module pages mount under                                         | [Distributable module](/docs/building/distributable-module#module-navigation-and-access) |
| The backend builds and starts but the dashboard never lists your page              | The pages barrel is never imported, so the `@RegisterPage` decorators never run                                  | [Pages & components](/docs/building/pages-and-components#declare-a-page)                 |
| With several tabs open, pages hang loading and requests stay pending                 | The browser's six HTTP/1.1 connections per host are taken by long-lived streams. The dashboard is served over plain HTTP from a host name other than `localhost`, so the tabs cannot share their realtime stream | [Deployment](/docs/building/deployment#http2-and-long-lived-streams) |
| Live pages poll instead of updating live, and `POST /api/realtime/session` answers `{ ok: false }` | A proxy between the browser and the backend drops the `x-realtime-connection` or `x-realtime-session` header | [Deployment](/docs/building/deployment#http2-and-long-lived-streams) |
| Realtime events, presence, or notifications don't reach users on another instance  | The in-memory realtime driver does not cross process boundaries. More than one instance needs Redis              | [Configuration](/docs/building/configuration#realtime-transport-driver)                 |
| Publishing to a topic reaches no subscriber                                        | The topic is not registered on any page. Topics are bound to pages                                                | [Backend services](/docs/building/backend-services#realtime)                             |
| The UI shows a raw `dms.x.y` key instead of text                                   | The `$`-prefixed key is missing from one or more locale files                                                    | [Localization](/docs/building/localization)                                              |
| Your layer's `Foo.vue` doesn't override the base `<DmsFoo>`                        | A different full component name, or your layer's `priority` is too low. Higher numbers register first                            | [Frontend layer](/docs/building/frontend-layer#overriding-an-existing-component)         |

Layer source edits normally propagate through the development watcher. If an edit stays stale, restart the backend first, then the frontend ([Project setup](/docs/building/project-setup#running)). For a blank pane, check both the browser console and the full registered component name. A name mismatch can render an empty `div` without an error.
