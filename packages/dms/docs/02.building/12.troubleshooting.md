# Troubleshooting

The recurring failure modes of DMS development look alike from the outside — a blank pane, a 404, a stale screen — while their causes live in different parts of the stack. Each symptom below maps to its cause and to the section that explains it; the linked sections own the full story.

| Symptom                                                                            | Cause                                                                                                            | Explained in                                                                             |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| A custom component renders blank, no console error                                 | Auto-import name mismatch: with `pathPrefix: false` the name is prefix + filename only, and Vue stays silent     | [Frontend layer](/docs/building/frontend-layer#component-naming)                         |
| A `CustomComponent` pane is blank, console shows a `[resolveDmsComponent]` warning | The backend string and the registered component name disagree after normalization; the catch-all renders a `div` | [Custom component](/docs/components/custom-component#the-name-must-resolve)              |
| You edit layer code but the dashboard shows the old version                        | The dev server serves the materialized layer copy, and a watcher missed the edit                               | [Frontend layer](/docs/building/frontend-layer#the-materialized-layer-cache-is-a-physical-copy)  |
| Boot fails with `Unresolved interface dependencies: <module> requires <package>`   | A dependency carrying an `antelopeJs` manifest that no loaded module declares in `implements` — a runtime package other modules import from must declare its own name | [Distributable module](/docs/building/distributable-module#the-module-manifest-antelopejs-in-packagejson) |
| The backend builds clean but the page 500s when opened                             | A Vue template or compile error in the layer — `tsc` never compiles the frontend module                               | [Frontend layer](/docs/building/frontend-layer)                                          |
| A link or `router.push` to a module page 404s                                      | The path omits the `/modules/<moduleId>` prefix module pages mount under                                         | [Distributable module](/docs/building/distributable-module#module-navigation-and-access) |
| The backend builds and starts but the dashboard never lists your page              | The pages barrel is never imported, so the `@RegisterPage` decorators never run                                  | [Pages & components](/docs/building/pages-and-components#declare-a-page)                 |
| Realtime events, presence, or notifications don't reach users on another instance  | The in-memory realtime driver — it does not cross process boundaries; multi-instance needs Redis                 | [Configuration](/docs/building/configuration#realtime--transport-driver)                 |
| Publishing to a topic reaches no subscriber                                        | The topic is not registered on any page — topics are page-bound                                                  | [Backend services](/docs/building/backend-services#realtime)                             |
| The UI shows a raw `dms.x.y` key instead of text                                   | The `$`-prefixed key is missing from one or more locale files                                                    | [Localization](/docs/building/localization)                                              |
| Your layer's `Foo.vue` doesn't override the base `<DmsFoo>`                        | A different prefix, or your layer loses the `priority` precedence (lower number wins)                            | [Frontend layer](/docs/building/frontend-layer#overriding-an-existing-component)         |

Two habits shortcut most of these. After editing layer source, full-restart both processes — backend first, then frontend — before debugging anything that looks new ([Project setup](/docs/building/project-setup#running)). And when a pane is blank, check the browser console first: a resolver warning distinguishes a name mismatch from a genuinely empty component.
