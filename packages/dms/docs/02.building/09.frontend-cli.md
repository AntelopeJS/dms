The `ajs dms` command ships with `@antelopejs/dms-frontend`, the frontend loader. It reads the frontend modules of your AntelopeJS project, assembles them into one Vue workspace, and runs, builds or serves that workspace. The loader has its own package, release cycle and documentation.

::tip{to="/docs/frontend"}
The **[Frontend](/docs/frontend)** section holds the complete reference. It lists every command and flag and the environment variables. It also covers the frontend modules a layer ships, server rendering, and how to deploy the frontend server.
::

## Commands for building a dashboard

| Command                   | When                                                                                                                                  |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `ajs dms dev`             | Day to day, next to `ajs project dev -w`, run from the project. Finds the project's running backend from `.antelope/dev.json` and reloads on every edit. |
| `ajs dms build -e <env>`  | Before a deployment. Builds the frontend from `antelope.config.ts` and the installed modules, without a backend. `-e` defaults to `production`. |
| `ajs dms start -b <url>`  | In production. Serves the built frontend against the backend at `<url>`.                                                              |
| `ajs dms clean -b <url>`  | When a dev workspace is stale. Removes the workspace of that backend. `--all` removes every workspace after a confirmation.            |

```bash [Terminal]
# terminal 1: the backend
ajs project dev -w

# terminal 2: the frontend, on http://localhost:3001
ajs dms dev
```

`ajs dms` reads the environment of the shell it runs in, then `.env.local` and `.env` in the current directory. A variable set in the shell wins over both files. `ajs dms help environment` lists the variables.

Outside the project, `ajs dms dev -b <url>` needs `--project <dir>` to find the modules.

The DMS frontend module names the loader releases it runs on in `engines["@antelopejs/dms-frontend"]` of its `package.json`. The loader reads that field before it builds.
