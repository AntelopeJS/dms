# Frontend CLI

The **`ajs-dms`** binary, shipped by `@antelopejs/dms-frontend`, runs the shared DMS Vue dashboard frontend: the Vite dev server, production build and server, frontend-module preparation, and workspace cleanup. For the machine the CLI drives — layers, config, and the catch-all renderer — see [Frontend layer](/docs/building/frontend-layer).

The CLI reads the invoking process's environment, not the backend's `.env` file. Export `DMS_SESSION_SECRET` with at least 32 characters in the frontend terminal, or use a project script that loads `.env` before launching the CLI. Keep secrets server-side; never expose them through public frontend configuration.

## Commands and flags

`ajs-dms` has five commands. They don't all take the same flags — the set varies per command:

- `-b, --backend-url <url>` (env `DMS_API_BASE_URL`): `dev`, `build`, `start`, `prepare`, `clean`.
- `-p, --port <port>` (default `3001`, env `PORT`): `dev`, `start` only.
- `-f, --force` (reinstall deps): `dev`, `build`, `prepare`.
- `--offline` (reuse the cached manifest, env `DMS_OFFLINE`): `dev`, `build`, `prepare`.
- `--bootstrap-secret <secret>` (env `DMS_BOOTSTRAP_SECRET`): `dev`, `build`, `prepare`.
- `-a, --all` (clean every workspace): `clean` only.

| Command   | Purpose                                                                                                                                                                                                 | Backend URL                |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| `dev`     | Dev server with HMR. Reserves the frontend port first and sends it to the backend so it can whitelist the origin for CORS. Copies each layer into the workspace and watches the source to mirror edits. | Auto-discovers (see below) |
| `prepare` | Prepare the generated Vite workspace and frontend-module registry. Meant to run as a module's `postinstall`.                                                                                           | Optional — **CI-friendly** |
| `build`   | Download matching layers, then build the client in `dist/client`, SSR in `dist/ssr`, and email renderer and locale data in `dist/server`.                                                               | **Required**               |
| `start`   | Run `server.mjs` from the selected renderer's built workspace.                                                                                                                                          | **Required**               |
| `clean`   | Remove workspace artifacts. `-a/--all` cleans every workspace.                                                                                                                                          | `-b` or `--all`            |

::note
`prepare` exits **0** (with a warning) when no backend URL is set or the backend is unreachable. That's deliberate: a layer's `postinstall` calling `ajs-dms prepare` must not break a CI `install` when no backend is running.
::

## How `dev` finds the backend

`dev` resolves the backend URL in order:

1. An explicit `-b` / `DMS_API_BASE_URL`.
2. Otherwise it walks up from the current directory for a `.antelope/dev.json` (written by a running `ajs project dev`), validates the recorded `pid` is alive, and reads the API endpoint from it (rewriting a wildcard host like `0.0.0.0` to `localhost`).

It stops at the **first** `.antelope/dev.json` it finds, so it won't accidentally attach to a parent project's backend. `build`, `start`, and `clean` do **not** auto-discover — give them `-b`.

## Authenticating to the backend

The two routes `ajs-dms` fetches — the manifest and the modules ZIP — carry each module's private options and full source, so the backend gates them behind [`frontend.bootstrapSecret`](/docs/building/configuration#frontend--layer-distribution). `ajs-dms` resolves the credential to present in order:

1. An explicit `--bootstrap-secret` / `DMS_BOOTSTRAP_SECRET`. Prefer the environment variable — a secret on the command line is visible to every process on the machine.
2. `dev` and `prepare` then walk up for the project's `.antelope/dms-dev.json`, which a development backend publishes for exactly this purpose. So the local loop needs no configuration at all.

A discovered credential is presented **only to the backend that published it** — `ajs-dms` compares the URL it is about to call against the api endpoint in that project's own `.antelope/dev.json`. Point `-b` at a staging or production host from inside a running project and the local credential is withheld rather than sent to it.

`build` uses **only** the explicit value: quietly authenticating a production build with a local dev instance's credential would fail far from its cause. `start` needs no credential because it does not fetch the layer manifest or source archive.

A refused credential is fatal for `dev` and `build`, and it never falls back to the cached manifest: that cache can still hold private options from a previously-authorized run, and replaying them would defeat the gate. `prepare` keeps its exit-0 contract and falls back to a workspace-less prepare.

::warning
Refusal only happens on a backend configured [`requireBootstrap: "enforce"`](/docs/building/configuration#frontend--layer-distribution). The default, `"warn"`, answers an unauthenticated caller with a `200` whose private options have been removed — so nothing fails and the build succeeds. `ajs-dms` warns whenever the modules arrive with no private options at all, which is the only client-side signal that this happened.
::

::note
Against a backend that does not recognize the credential, `dev` fails with a message naming both remedies — it cannot work from a manifest with no layer source paths, which the backend serves only to authenticated callers on the same machine.
::

::warning
Workspaces are isolated per backend under `~/.antelopejs/dms-frontend/<hash>/` (each with its own `node_modules`, manifest cache, and client storage scope). Reset one with `ajs-dms clean -b <url>`, or remove every workspace with `ajs-dms clean --all`.
::
