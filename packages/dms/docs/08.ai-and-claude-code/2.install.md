The `antelopejs` plugin for [Claude Code](https://claude.com/claude-code) and [Codex](https://developers.openai.com/codex) lives in the [AntelopeJS/agent-skills](https://github.com/AntelopeJS/agent-skills) repository. It keeps the project's skills folder in sync with the skills your installed packages ship: the framework skills of `@antelopejs/core`, the DMS skills, `dms-frontend` and the skill of each `dms-*` module. The [skill catalog](/docs/ai-and-claude-code/skill-catalog) lists them all.

## What the plugin unlocks

Until the skills are synced, Claude Code and Codex know only what they read in your code. With the plugin, they load the AntelopeJS skill that matches the task, written for the version your project installs:

- **Framework.** `antelopejs`, `ajs-cli`, `ajs-consume-interface` and `ajs-author-interface` from `@antelopejs/core`: modules, interface contracts and the `ajs` CLI.
- **DMS.** `dms`, `dms-pages`, `dms-auth`, `dms-module` and the rest of the suite, plus `dms-frontend`: pages, blocks, permissions and frontend modules.
- **Modules.** The skills of each installed `dms-*` module. `@antelopejs/dms-assistant` brings `dms-external-database`, which connects an existing PostgreSQL, MongoDB or RethinkDB database and maps it into pages through the builder, and `dms-page-design`, which designs those pages.
- **The plugin's own skills.** Sync the skills, list them, look up an interface contract, scaffold a module and evaluate skills.

::note
`dms-external-database` calls builder and database tools such as `builder_analyse_database`. In the dashboard chat, `dms-assistant` provides them. In your own Claude Code session, the `dms` server that `ajs project dev` adds to the project's `.mcp.json` serves tools of the same names, under the `mcp__dms__` prefix. [MCP server](/docs/ai-and-claude-code/mcp-server) shows the setup, for Codex too.
::

## How a skill reaches the agent

::steps{level="3"}
### A package declares its skills

A package lists its skill folders under `antelopeJs.skills` in its `package.json`. Each subfolder holds a `SKILL.md` whose `description` says what the skill does and when to use it. `@antelopejs/dms` declares `./skills`, and so does every `dms-*` module.

### The plugin links each skill where the agent looks

The plugin links each skill into the project's `.claude/skills/` for Claude Code and `.agents/skills/` for Codex. The [`dms-assistant` module](/docs/ai-and-claude-code/dms-assistant) reads the same declarations by itself and needs no plugin.

### The agent picks a skill by its description

The agent keeps every skill's description in view and loads the body of a skill only when the task matches it. A package you did not install brings no skill, and an upgraded package brings its upgraded skill.
::

## Add the plugin

Run these commands once. The install lands in your user scope, so every project sees it.

::tabs
:::tabs-item{label="Claude Code" icon="i-lucide-terminal"}
```bash [Terminal]
claude plugin marketplace add AntelopeJS/agent-skills
claude plugin install antelopejs@antelopejs
```

The same commands from inside a session:

```text [Inside Claude Code]
/plugin marketplace add AntelopeJS/agent-skills
/plugin install antelopejs@antelopejs
```

Restart the session, or run `/reload-plugins`, to load the plugin. From then on, its hooks sync the skills into `.claude/skills/`. To install the plugin for one repository only, add `--scope project` to both commands. Claude Code then records it in that repository's `.claude/settings.json`.
:::

:::tabs-item{label="Codex" icon="i-lucide-code"}
```bash [Terminal]
codex plugin marketplace add AntelopeJS/agent-skills
codex plugin add antelopejs@antelopejs
```

Once the marketplace is added, you can also install `antelopejs` from `/plugins` in Codex, or from the plugins directory of the desktop app.

Then open `/hooks` in Codex and trust the `antelopejs` entries. Codex runs a plugin's hooks only once you trust them, and asks again after every plugin update. The trusted hooks sync the skills into `.agents/skills/`.

Until you trust the hooks, run the sync from the project root, and again after you install or upgrade packages:

```bash [Terminal]
npx -y github:AntelopeJS/agent-skills sync --target codex
```
:::
::

::note
The sync works without the plugin. `npx -y github:AntelopeJS/agent-skills sync` links the skills into both `.claude/skills/` and `.agents/skills/`, where any agent that reads those folders finds them. Replace `sync` with `list` to see what it finds.
::

### Projects created from a template

[`template-dms-demo`](https://github.com/AntelopeJS/template-dms-demo) and [`template-dms-adonis`](https://github.com/AntelopeJS/template-dms-adonis) ship a `.claude/settings.json` that declares the marketplace and enables the plugin. Once you trust the folder, Claude Code offers to install the plugin. Accept it, and there is nothing else to do. The `AGENTS.md` of each template gives Codex the sync command.

```json [.claude/settings.json]
{
  "extraKnownMarketplaces": {
    "antelopejs": {
      "source": { "source": "github", "repo": "AntelopeJS/agent-skills" }
    }
  },
  "enabledPlugins": {
    "antelopejs@antelopejs": true
  }
}
```

To give every Claude Code contributor the same prompt in an existing project, commit the same file.

## How the sync works

The plugin's hooks run the sync at session start and after every Bash command. A `pnpm install`, or an `ajs` command that adds a module, brings the new skills into the running session.

- **Which projects.** A directory that holds an `antelope.config.*` file, or an app whose `package.json` depends on `@antelopejs/core`, such as the embedded runtime of the AdonisJS template. Anywhere else the sync does nothing.
- **Where it looks.** The first match for each package wins, in this order:
  1. The workspace: the current package, its parent folders up to the repository root, and the packages listed in the root's `pnpm-workspace.yaml` or `package.json` `workspaces`. Source checkouts and module playgrounds resolve here.
  2. `.antelope/cache`, where `ajs` downloads the modules declared in `antelope.config.ts`, so the skills match the module version that runs.
  3. The dependencies of those packages, each looked up from that package's own folder. This brings the interface packages a module installs for itself.
  4. `node_modules` of the project and of the workspace root, pnpm's symlinks included.

  An installed package that declares `antelopeJs.implements` counts as a module: it is checked right after `.antelope/cache`, before the dependencies, and its own dependencies join step 3.

  A package is found once, at the first place that has it, even when that copy ships no skills: a cached module that declares none hides the installed copy, because the cached one is what runs.
- **What it creates.** One relative symlink per skill, named `<package>--<skill>` after the package's short name: `dms--dms-pages`, `dms-frontend--dms-frontend`, `dms-mailing--dms-mailing`. The link goes through `node_modules/<package>`, so the skill matches the installed version after an upgrade.
- **What it leaves alone.** The sync records its entries in a `.ajs-managed.json` file in each skills folder and lists them in a generated `.gitignore` next to it, so git ignores them. It reports and skips a skill of yours with the same name, and never overwrites it. It removes the entries whose package is gone.

The plugin's skills run the sync and list its result. Call them as `/antelopejs:<name>` in Claude Code and as `$antelopejs:<name>` in Codex.

| Command | Use it to |
| ------- | --------- |
| `/antelopejs:skills` | List the synced skills and the package each one comes from. |
| `/antelopejs:sync-skills` | Sync now and see what changed. |
| `/reload-skills` | Load the synced skills in Claude Code when `.claude/skills/` did not exist at session start. |
| `npx -y github:AntelopeJS/agent-skills list` | List the skills and their sync status in both folders. |
| `npx -y github:AntelopeJS/agent-skills sync --target codex` | Sync `.agents/skills/` for Codex. Restart Codex if a skill does not appear. |

::tip
If `/antelopejs:skills` lists no DMS skill, the packages are not installed yet. Run `pnpm install`. The modules that `antelope.config.ts` declares arrive in `.antelope/cache` on the first `ajs project dev`. Then sync again.
::

## Update and uninstall

The synced skills follow your packages, not the plugin. Upgrade `@antelopejs/core`, `@antelopejs/dms` or a module, and the next sync points at the new version.

::tabs
:::tabs-item{label="Claude Code" icon="i-lucide-terminal"}
Update the marketplace, then the plugin:

```bash [Terminal]
claude plugin marketplace update antelopejs
claude plugin update antelopejs@antelopejs
```

To remove the plugin, uninstall it and remove the marketplace. If you installed it for one repository, add `--scope project` to `uninstall` and remove the two keys from that repository's `.claude/settings.json`.

```bash [Terminal]
claude plugin uninstall antelopejs@antelopejs
claude plugin marketplace remove antelopejs
```
:::

:::tabs-item{label="Codex" icon="i-lucide-code"}
Update the marketplace and the installed plugin, then trust the hooks again in `/hooks`:

```bash [Terminal]
codex plugin marketplace upgrade antelopejs
```

To remove the plugin, uninstall it and remove the marketplace:

```bash [Terminal]
codex plugin remove antelopejs@antelopejs
codex plugin marketplace remove antelopejs
```
:::
::

To remove the synced skills from a project, delete the entries that `.claude/skills/.ajs-managed.json` and `.agents/skills/.ajs-managed.json` list. Then delete those two files and the `.gitignore` next to each.
