# Install in Claude Code

Claude Code reads skills from the `antelopejs` plugin. The plugin brings the framework skills and keeps `.claude/skills/` in sync with the skills your installed packages ship, including the DMS, `dms-frontend` and every `dms-*` module. The [skill catalog](/docs/ai-and-claude-code/skill-catalog) lists them all.

::warning
The [claude-antelopejs](https://github.com/AntelopeJS/claude-antelopejs) repository is **internal** to the AntelopeJS organization today. Claude Code clones it with your own git credentials, so you need read access to it on GitHub (an SSH key loaded in `ssh-agent`, or a stored HTTPS credential such as `gh auth login` then `gh auth setup-git`). Without access, `marketplace add` fails with a clone error.
::

## How a skill reaches the agent

::steps{level="3"}
### A package declares its skills

A package lists its skill folders under `antelopeJs.skills` in its `package.json`. Each subfolder holds a `SKILL.md` whose `description` says what the skill does and when to use it. `@antelopejs/dms` declares `./skills`; so does every `dms-*` module.

### The skill lands where the agent looks

In Claude Code, the `antelopejs` plugin links each skill into the project's `.claude/skills/`. In the dashboard, the [dms-ai assistant](/docs/ai-and-claude-code/dms-ai) reads the same declarations from every loaded module, with no plugin.

### The agent picks it by description

The agent keeps every skill's description in view and loads a skill's body only when the task matches it. A skill nobody installed never shows up, and an upgraded package brings its upgraded skill.
::

## Add the plugin

Run these two commands once. The install lands in your user scope, so every project sees it:

::code-group
```bash [Terminal]
claude plugin marketplace add AntelopeJS/claude-antelopejs
claude plugin install antelopejs@antelopejs
```

```text [Inside Claude Code]
/plugin marketplace add AntelopeJS/claude-antelopejs
/plugin install antelopejs@antelopejs
```
::

Restart the session, or run `/reload-plugins`, to load it. To install it for one repository only, add `--scope project` to both commands: Claude Code records it in that repository's `.claude/settings.json`.

### Projects created from a template

[template-dms-demo](https://github.com/AntelopeJS/template-dms-demo) and [template-dms-adonis](https://github.com/AntelopeJS/template-dms-adonis) ship a `.claude/settings.json` that declares the marketplace and enables the plugin. Claude Code offers to install it once you trust the folder: accept, and there is nothing else to do.

```json [.claude/settings.json]
{
  "extraKnownMarketplaces": {
    "antelopejs": {
      "source": { "source": "github", "repo": "AntelopeJS/claude-antelopejs" }
    }
  },
  "enabledPlugins": {
    "antelopejs@antelopejs": true
  }
}
```

Commit the same file in an existing project to give every contributor the same prompt. Contributors still need read access to the repository.

## How the sync works

The plugin syncs at session start and again after every Bash command, so a `pnpm install` or an `ajs` run that adds a module brings its skills into the running session.

- **Which projects.** A directory holding an `antelope.config.*` file, or an app whose `package.json` depends on `@antelopejs/core`: an embedded runtime such as the AdonisJS template. Anywhere else the sync does nothing.
- **Where it looks**, the first hit per package winning:
  1. the **workspace**: the current package, its parents up to the repository root, and the packages of the root's `pnpm-workspace.yaml` or `workspaces` field (source checkouts and module playgrounds);
  2. **`node_modules`** of the project and of the workspace root, pnpm's symlinks included;
  3. **`.antelope/cache`**, where `ajs` downloads the modules declared in `antelope.config.ts`.
- **What it creates.** One relative symlink per skill, named `<package>--<skill>` after the package's short name: `dms--dms-pages`, `dms-frontend--dms-frontend`, `dms-mailing--dms-mailing`. The link follows the installed package, so the skill always matches its version.
- **What it leaves alone.** It records its entries in `.claude/skills/.ajs-managed.json` and lists them in a generated `.claude/skills/.gitignore`, so your repository stays clean. A skill of yours with the same name is reported and skipped, never overwritten, and entries whose package disappeared are removed.

| Command | Use it to |
| ------- | --------- |
| `/antelopejs:skills` | List the synced skills and the package each one comes from. |
| `/antelopejs:sync-skills` | Force a sync now and see what changed. |
| `/reload-skills` | Load the synced skills when `.claude/skills/` did not exist at session start. |

::tip
No DMS skill in `/antelopejs:skills`? The packages are not installed yet. Run `pnpm install`, then `pnpm exec ajs project modules install` for the modules declared in `antelope.config.ts`, then `/antelopejs:sync-skills`.
::

## Update and uninstall

Update the plugin with the marketplace, then the plugin itself:

```bash [Terminal]
claude plugin marketplace update antelopejs
claude plugin update antelopejs@antelopejs
```

The synced skills follow your packages, not the plugin: upgrade `@antelopejs/dms` or a module, and the next sync points at the new version.

To remove the plugin, uninstall it and drop the marketplace. Add `--scope project` to `uninstall` when it was installed for one repository, and remove the two keys from that repository's `.claude/settings.json`:

```bash [Terminal]
claude plugin uninstall antelopejs@antelopejs
claude plugin marketplace remove antelopejs
```

To drop the synced skills from a project, delete the entries listed in `.claude/skills/.ajs-managed.json`, then that file and `.claude/skills/.gitignore`.
