---
title: "Ship a skill with your module"
description: Teach Claude Code, Codex and the DMS AI assistant how to use your module by shipping a SKILL.md file next to its code, declared in package.json.
mode: how-to
---

A module that ships a skill tells every agent when and how to use it, in the version the project installed. The `antelopejs` plugin links the skill into Claude Code and Codex, and the `dms-ai` assistant loads it. There is nothing else to configure.

::steps{level="3"}
### Write the skill

Create one folder per skill under `skills/`. Each folder holds a `SKILL.md` whose frontmatter has a `name` and a `description` that says when to use the skill:

```md [skills/dms-cookbook/SKILL.md]
---
name: dms-cookbook
description: Adds recipes, ingredients and meal plans to a DMS project with @acme/dms-cookbook. Use when the user wants recipe pages, a meal planner, or asks about the cookbook module.
icon: i-lucide-chef-hat
category: content
tags: [recipes, meal plans]
---

# Cookbook

Load the module in `antelope.config.ts`, then …
```

The **Skills** page of the `dms-ai` assistant also reads the optional `icon`, `category` and `tags` fields to draw the skill's card.

### Declare it

In `package.json`, list the folder that holds your skills under `antelopeJs.skills`, and add it to `files` so that it ships with the package:

```json [package.json]
{
  "files": ["dist", "frontend-vue", "skills"],
  "antelopeJs": {
    "skills": ["./skills"]
  }
}
```

### Check that it loads

In a project that installs your module, run `/antelopejs:sync-skills` in Claude Code. The skill appears as `.claude/skills/<package>--dms-cookbook`, where `<package>` is the package name without its scope. `npx -y github:AntelopeJS/agent-skills sync` fills both `.claude/skills` and `.agents/skills`, the folder Codex reads. For the `dms-ai` assistant, restart the backend, then open **Assistant**, then **Skills**.
::

## Write the skill for an agent

- **Lead with when.** The agent always reads the `description`, and reads the body only when the description matches. Name the cases that should trigger the skill.
- **Keep it short.** Put the steps in `SKILL.md`. Move long reference material into a `REFERENCE.md` next to it, and link that file from the body.
- **Route instead of repeating.** For pages, auth and the dev servers, point to the `dms-*` skills instead of restating them.
- **Keep it current.** The skill ships with each release of your package, so update it with the API it describes.
