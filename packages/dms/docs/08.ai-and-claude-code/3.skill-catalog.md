# Skill catalog

The suite is a set of skills spread over the packages they describe. An agent sees every skill's description at all times and loads the body when a task matches it, so the "Triggers when" column below is what decides which skill answers. Each skill ships with the package in the "Shipped by" column: it reaches your agent only when the project installs that package.

::tip
In Claude Code, run `/antelopejs:skills` to list the skills synced into your project and the package each comes from; elsewhere, including Codex, run `npx -y github:AntelopeJS/agent-skills list`. In the dashboard, open **Assistant → Skills**.
::

## Framework

Shipped by `@antelopejs/core`, so every AntelopeJS project has them, in the version of the `ajs` CLI it installs. They arrive with the first core release after 1.15.2; with an older core, upgrade `@antelopejs/core` to get them.

| Skill | Triggers when | Docs |
| ----- | ------------- | ---- |
| `antelopejs` | Any work in an AntelopeJS project, module or interface repository; it routes to the skills below and to those synced from your packages. | [Overview](/docs/ai-and-claude-code/overview) |
| `ajs-cli` | Creating, running, building, testing or managing modules with the `ajs` CLI. Everything under `ajs dms` goes to `dms-frontend`. | [Installation](/docs/getting-started/installation) |
| `ajs-consume-interface` | Importing, calling or implementing an AntelopeJS interface, or fixing an unresolved one. | [Interfaces](/docs/interfaces) |
| `ajs-author-interface` | Authoring or versioning an interface package, or deciding whether a change is breaking. | [Distributable module](/docs/building/distributable-module) |

## Plugin

The `antelopejs` plugin, from the [agent-skills](https://github.com/AntelopeJS/agent-skills) repository, ships no skill: it syncs the skills of your packages and resolves interface contracts, for Claude Code and Codex alike. It is the only part you install yourself; see [Install the plugin](/docs/ai-and-claude-code/install). The commands below are Claude Code slash commands; in Codex, the sync runs with `npx -y github:AntelopeJS/agent-skills sync --target codex` and the resolver with `npx -y github:AntelopeJS/agent-skills interface`.

| Command | Does |
| ------- | ---- |
| `/antelopejs:interface <name> [subpath]` | Looks up an interface contract: surface, versions or full TSDoc. |
| `/antelopejs:new-module <path>` | Scaffolds a module and wires its interface dependencies. |
| `/antelopejs:sync-skills` | Syncs the skills shipped by the project's packages into `.claude/skills/` now, and reports what changed. |
| `/antelopejs:skills` | Lists the synced skills and the package that ships each one. |

| `dms-module` | Packaging a distributable DMS module: its `antelopeJs` manifest, `RegisterModule`, its interface package and its own skill. | [Distributable module](/docs/building/distributable-module) |
| `dms-pages` | Adding a screen: a `PageController` page, its blocks, data types and the routes that feed them. | [Pages and components](/docs/building/pages-and-components) |
| `dms-auth` | Protecting a route or page, registering permissions, or working with users, roles and tenants. | [Auth and permissions](/docs/auth-and-tenancy/auth-and-permissions) |
| `dms-best-practices` | Before creating or changing any page or custom block, and whenever the user hands over a mockup or screenshot. | [Best practices](/docs/ai-and-claude-code/best-practices) |

## Modules

Each `dms-*` module ships one skill that says when and how to use it. It reaches your agent once the project installs the module.

| Skill | Shipped by | Triggers when | Docs |
| ----- | ---------- | ------------- | ---- |
| `dms-api` | `@antelopejs/dms-api` | Configuring the API console, or debugging a failing or slow route from its request logs. | [API](/docs/modules/api/introduction) |
| `dms-automation` | `@antelopejs/dms-automation` | Configuring automation, or creating, importing or debugging a procedure and its runs. | [Automation](/docs/modules/automation/introduction) |
| `dms-automation-interface` | `@antelopejs/interface-dms-automation` | Declaring trigger, action or data node types from another module, or invoking a procedure from code. | [Extending automation](/docs/modules/automation/extending) |
| `dms-builder` | `@antelopejs/dms-builder` | Configuring the page builder, or calling its interface or HTTP API. | [Builder](/docs/modules/builder/introduction) |
| `dms-database` | `@antelopejs/dms-database` | Configuring the database console, deep-linking to its pages, or explaining why a table is missing from it. | [Database](/docs/modules/database/introduction) |
| `dms-lang` | `@antelopejs/dms-lang` | Adding or translating i18n keys, overriding a module's texts, or serving a translation workspace to another app. | [Languages](/docs/modules/lang/introduction) |
| `dms-mailing` | `@antelopejs/dms-mailing` | Sending a template from code, reporting provider events, or designing e-mail templates. | [Mailing](/docs/modules/mailing/introduction) |
| `dms-marketing` | `@antelopejs/dms-marketing` | Embedding the tracker, sending custom events or A/B variations, or defining funnels and tests. | [Marketing](/docs/modules/marketing/introduction) |
