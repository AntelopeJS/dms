An agent sees every skill's description and loads the body of a skill when a task matches it. The "Triggers when" column summarizes that description. A skill reaches your agent only when the project installs the package that ships it. Interface packages such as `@antelopejs/interface-api` also ship a skill about their contract. This page does not list them, and `list` shows the ones your project has.

::tip
To list the skills synced into your project and the package each comes from, run `/antelopejs:skills` in Claude Code or `npx -y github:AntelopeJS/agent-skills list` in an AntelopeJS project. In the dashboard, open **Assistant**, then **Skills**.
::

## Framework

Shipped by `@antelopejs/core`, so every AntelopeJS project has them.

| Skill | Triggers when | Docs |
| ----- | ------------- | ---- |
| `antelopejs` | Any work in an AntelopeJS project, module or interface repository. It routes to the skills below and to those synced from your packages. | [Overview](/docs/ai-and-claude-code/overview) |
| `ajs-cli` | Creating, running, building, testing or managing modules with the `ajs` CLI, or starting AntelopeJS inside an existing Node.js server with `createRuntime`. Everything under `ajs dms` goes to `dms-frontend`. | [Installation](/docs/getting-started/installation) |
| `ajs-consume-interface` | Declaring or importing an interface dependency, providing one with `ImplementInterface`, or fixing an interface import that does not resolve. | [Interfaces](/docs/interfaces) |
| `ajs-author-interface` | Authoring or versioning an interface package, or deciding whether a change is breaking. | [Distributable module](/docs/building/distributable-module) |

## Plugin

The `antelopejs` plugin from the [agent-skills](https://github.com/AntelopeJS/agent-skills) repository ships five skills of its own, for Claude Code and Codex alike. [Install the plugin](/docs/ai-and-claude-code/install) covers the setup. Call a plugin skill as `/antelopejs:<name>` in Claude Code and as `$antelopejs:<name>` in Codex. Without the plugin, `npx -y github:AntelopeJS/agent-skills sync` runs the sync and `npx -y github:AntelopeJS/agent-skills interface` runs the contract resolver.

| Skill | Does |
| ----- | ---- |
| `antelopejs:interface` | Looks up an interface contract: its exports, its versions or its full TSDoc. |
| `antelopejs:new-module` | Scaffolds a module with `ajs module init` and wires its interface dependencies. |
| `antelopejs:sync-skills` | Syncs the skills shipped by the project's packages now, and reports what changed. |
| `antelopejs:skills` | Lists the synced skills and the package that ships each one. |
| `antelopejs:eval-skills` | Runs the skill evals and produces an eval report. |

## Core DMS

Shipped by `@antelopejs/dms`, so every DMS project has them.

| Skill | Triggers when | Docs |
| ----- | ------------- | ---- |
| `dms` | The user mentions the DMS, or builds an app, admin page or dashboard on it. It gives the mental model and routes to the other skills. | [Architecture](/docs/getting-started/architecture) |
| `dms-project` | Creating or configuring a DMS app (`antelope.config.ts`, the `src/index.ts` lifecycle, `AddFrontendModule`, or the embedded mode of an AdonisJS app), or starting, stopping or restarting its dev servers and reading their logs. | [Project setup](/docs/building/project-setup), [AdonisJS](/docs/getting-started/adonisjs) |
| `dms-module` | Packaging a distributable DMS module: its `antelopeJs` manifest, `RegisterModule` and its own interface package. | [Distributable module](/docs/building/distributable-module) |
| `dms-pages` | Adding a screen: a `PageController` page, its blocks, data types and the routes that feed them. | [Pages and components](/docs/building/pages-and-components) |
| `dms-auth` | Protecting a route or page, registering permissions, or working with users, roles and tenants. | [Auth and permissions](/docs/auth-and-tenancy/auth-and-permissions) |
| `dms-best-practices` | Creating or changing any page, before writing a `CustomComponent`, and whenever the user hands over a mockup or screenshot. | [Best practices](/docs/ai-and-claude-code/best-practices) |

## Modules

Each of these packages ships one skill that says when and how to use it. The skill reaches your agent once the project installs the package.

| Skill | Shipped by | Triggers when | Docs |
| ----- | ---------- | ------------- | ---- |
| `dms-api` | `@antelopejs/dms-api` | Configuring the API console, or debugging a failing or slow route from its request logs. | [API](/docs/modules/api/introduction) |
| `dms-automation` | `@antelopejs/dms-automation` | Configuring automation, or creating, importing or debugging a procedure and its runs. | [Automation](/docs/modules/automation/introduction) |
| `dms-automation-interface` | `@antelopejs/interface-dms-automation` | Declaring trigger, action or data node types from another module, or invoking a procedure from code. | [Extending automation](/docs/modules/automation/extending) |
| `dms-database` | `@antelopejs/dms-database` | Configuring the database console, deep-linking to its pages, or explaining why a table is missing from it. | [Database](/docs/modules/database/introduction) |
| `dms-lang` | `@antelopejs/dms-lang` | Adding or translating i18n keys, overriding a module's texts, or serving a translation workspace to another app. | [Languages](/docs/modules/lang/introduction) |
| `dms-mailing` | `@antelopejs/dms-mailing` | Sending a template from code, reporting provider events, or designing e-mail templates. | [Mailing](/docs/modules/mailing/introduction) |
| `dms-marketing` | `@antelopejs/dms-marketing` | Embedding the tracker, sending custom events or A/B variations, or defining funnels and tests. | [Marketing](/docs/modules/marketing/introduction) |
| `dms-media` | `@antelopejs/dms-media` | Adding an image or file field with `AssetType`, binding it to a folder and its permissions, or serving resized images. | [Media](/docs/modules/media/introduction) |
| `dms-saas` | `@antelopejs/dms-saas` | Configuring Stripe and plans, gating features by plan, or extending registration and invoices. | [SaaS](/docs/modules/saas/introduction) |
