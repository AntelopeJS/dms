An agent sees every skill's description, and loads the body of a skill when a task matches it. The "Triggers when" column sums up that description. A skill reaches your agent only when the project installs the package that ships it.

Interface packages such as `@antelopejs/interface-api` also ship a skill about their contract. This page does not list them.

::tip
To list the skills synced into your project and the package each comes from, run `/antelopejs:skills` in Claude Code or `npx -y github:AntelopeJS/agent-skills list` in an AntelopeJS project. In the dashboard, open **Assistant**, then **Skills**.
::

## Plugin

The `antelopejs` plugin ships skills of its own, for Claude Code and Codex alike. [Install the plugin](/docs/ai-and-claude-code/coding-agent/install) covers the setup. Call a plugin skill as `/antelopejs:<name>` in Claude Code and as `$antelopejs:<name>` in Codex.

| Skill | Does |
| ----- | ---- |
| `antelopejs:interface` | Looks up an interface contract: its exports, its versions or its full TSDoc. |
| `antelopejs:new-module` | Scaffolds a module with `ajs module init` and wires its interface dependencies. |
| `antelopejs:sync-skills` | Syncs the skills shipped by the project's packages now, and reports what changed. |
| `antelopejs:skills` | Lists the synced skills and the package that ships each one. |
| `antelopejs:dms-best-practices` | Applies the rules of a DMS page when the agent creates or changes a page, before it writes a `CustomComponent`, and when you hand over a design or screenshot. See [Best practices](/docs/ai-and-claude-code/coding-agent/best-practices). |
| `antelopejs:dms-pages` | Adds a screen in code: a `PageController` page, its blocks, data types and the routes that feed them. See [Pages and components](/docs/building/pages-and-components). |
| `antelopejs:dms-builder-mcp` | Changes a project's pages through the builder MCP tools of `@antelopejs/dms` (`builder_catalog`, `builder_add_block`, `builder_compose_page` and the others), and detects whether the project has them. See [MCP server](/docs/ai-and-claude-code/mcp-and-tools/mcp-server). |
| `antelopejs:dms-external-database` | Connects a project to an existing Postgres, MySQL/MariaDB or MongoDB database, runs the builder's analysis of it, and generates table and stats pages over it. See [Existing database](/docs/existing-database). |
| `antelopejs:dms-page-design` | Designs pages that show data, such as an analytics, dashboard or table page, with its charts, KPIs and period. |
| `antelopejs:dms-mockup` | Mocks up an app in `mockups/<name>/spec.json` before any page is built, and applies the comments left on the mockup. See [Mockups](/docs/ai-and-claude-code/mockups). |
| `antelopejs:dms-mockup-build` | Builds the real pages from an approved mockup. See [Mockups](/docs/ai-and-claude-code/mockups). |

## How the sync finds skills

The plugin's hooks run the sync at session start and after every Bash command. A `pnpm install`, or an `ajs` command that adds a module, brings the new skills into the running session.

The sync runs in a directory that holds an `antelope.config.*` file, or in an app whose `package.json` depends on `@antelopejs/core`, such as the embedded runtime of the AdonisJS template. Anywhere else it does nothing.

It looks for each package in this order, and the first match wins:

1. The workspace: the current package, its parent folders up to the repository root, and the packages of the root's `pnpm-workspace.yaml` or `workspaces`.
2. `.antelope/cache`, where `ajs` downloads the modules that `antelope.config.ts` declares. The skills then match the module version that runs.
3. An installed package that declares `antelopeJs.implements`, which counts as a module.
4. The dependencies of the packages above, each looked up from that package's own folder.
5. `node_modules` of the project and of the workspace root.

A package is found once, at the first place that has it, even when that copy ships no skills.

The sync creates one relative symlink per skill, named `<package>--<skill>` after the package's short name, such as `dms--dms-auth`. The link goes through `node_modules/<package>`, so it follows an upgrade.

The sync records its entries in a `.ajs-managed.json` file in each skills folder, and lists them in a generated `.gitignore` next to it. It never overwrites a skill of yours with the same name. It removes the entries whose package is gone.

| Command | Use it to |
| --- | --- |
| `/antelopejs:skills` | List the synced skills and the package each one comes from. |
| `/antelopejs:sync-skills` | Sync now and see what changed. |
| `npx -y github:AntelopeJS/agent-skills list` | List the skills and their sync status in both folders. |
| `npx -y github:AntelopeJS/agent-skills sync --target codex` | Sync `.agents/skills/` for Codex. |
