---
title: "Design fidelity"
description: What an agent does with your mockup. It asks one framing question, then compares each component that differs with the closest DMS block and lets you keep, adjust or replace that block.
mode: explanation
---

A mockup rarely maps one to one onto DMS blocks. An agent that follows the `antelopejs:dms-best-practices` skill does not guess how faithful you want the result. It asks you, once for the whole screen and then once for each component that differs visibly.

## One framing question

Before it builds anything, the agent asks how faithful the result should be:

| Choice | What happens |
| ------ | ------------ |
| **Pixel perfect** | The agent reproduces the design. It still searches the catalog for each element, and builds a custom block only where no block or composition matches. |
| **DMS equivalents** | The agent maps every component onto its closest DMS block without asking again. A component that no block or composition covers still goes through the comparison. |
| **Component by component** (recommended) | The agent walks through the components that differ and lets you decide each one. |

## Component by component

For each component of the mockup, the agent finds the closest DMS block, through its options or a composition of blocks. Differences the theme absorbs, such as colors, spacing, radius and fonts, never trigger a question. A visible difference does: a different layout, a missing element or another kind of chart. For each visible difference, the agent runs the [path before any custom block](/docs/ai-and-claude-code/coding-agent/best-practices#before-any-custom-block). It can group several components in one preview and one question.

::steps{level="3"}
### The agent searches the catalog

The agent looks for the block, the block options or the composition of blocks that comes closest to the component.

### The agent shows the comparison

:::tabs
::::tabs-item{label="With the mockup tools" icon="i-lucide-pen-tool"}
The agent builds or updates a [mockup](/docs/ai-and-claude-code/mockups). Its page holds the closest DMS option, your design as the reference and a [sketch](/docs/ai-and-claude-code/mockups/nodes#sketches) of the custom block it would build. You comment on the mockup, and the agent applies your comments.
::::

::::tabs-item{label="Without them" icon="i-lucide-terminal"}
Without the mockup tools, the agent writes a short table. When the custom option is hard to picture, it adds a markup snippet.

| Your design | DMS block | Visible difference |
| ----------- | --------- | ------------------ |
| Revenue tile with an inline bar chart | `KpiCard` with a sparkline | A line instead of bars under the figure |
::::
:::

### The agent asks

The agent asks one closed question. In the DMS AI assistant, each answer is a button:

- **Keep the DMS block**
- **Adjust it through its options**
- **Build a custom block**

### The agent builds what you chose

A custom block follows the [best practices](/docs/ai-and-claude-code/coding-agent/best-practices). Only that block is custom, it carries `.meta()`, and the rest of the page stays DMS blocks.
::

::note
In Safe mode, the DMS AI assistant cannot build a custom block. It offers the closest DMS composition instead, and asks whether to switch to Code mode for that one block.
::

## Preview blocks yourself

To compare blocks before you design around them, use the [component catalog](/docs/components/overview). Many block pages have a live preview with controls. The pages of blocks that need backend data or page context say what the preview cannot show. To preview a whole tree, open the [block preview page](/docs/ai-and-claude-code/mcp-and-tools/block-preview-page) of a local DMS.
