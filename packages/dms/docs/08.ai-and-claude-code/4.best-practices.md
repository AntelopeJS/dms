# Best practices

Three rules keep a DMS page maintainable, permissionable and editable by the page builder and by agents. The `dms-best-practices` skill, shipped with `@antelopejs/dms`, makes Claude Code and the dms-ai assistant apply them on every page they build.

## 1. A page is always described as blocks

Describe every page on the backend as a tree of DMS blocks: a toolbar, a grid of cards, a table, a form. Never as one block that draws the whole screen.

Each block is a line in the roles editor, a target for `.watch()` reactivity, a widget a `PeriodSelector` can drive, and a node the page builder can move. One block for the whole screen gives up all of that at once.

::tabs
:::tabs-item{label="Good" icon="i-lucide-check"}
```ts [src/pages/orders.ts]
@RegisterPage()
export class OrdersPage extends PageController("orders", { displayName: "$shop.orders.title", category: shopCategory }) {
  static period = PeriodSelector({ id: "orders" });

  static kpis = Grid().child(
    "row",
    GridRow()
      .child("revenue", KpiCard({ title: "$shop.orders.revenue", fetchUrl: "/api/orders/revenue", periodScope: "orders" }))
      .child("count", KpiCard({ title: "$shop.orders.count", fetchUrl: "/api/orders/count", periodScope: "orders" })),
  );

  static table = TableView(OrdersDataAPI, { caption: "$shop.orders.list" });
}
```
:::

:::tabs-item{label="Bad" icon="i-lucide-x"}
```ts [src/pages/orders.ts]
@RegisterPage()
export class OrdersPage extends PageController("orders", { displayName: "Orders", category: shopCategory }) {
  // One Vue component draws the period picker, the KPIs and the table:
  // one permission, no period scope, nothing the page builder can edit.
  static screen = CustomComponent("ShopOrdersScreen");
}
```
:::
::

## 2. Build only the missing block

When a part of the screen has no DMS equivalent — a flow canvas, a seat map — build **that block only** as a [custom component](/docs/components/custom-component), and keep everything around it as DMS blocks described on the backend. Permissions stay granular, and the rest of the page keeps the theme, the period, the live state and the editor for free.

## 3. Every custom block carries `.meta()`

Every custom block declares its name, description and icon with `.meta()`, as i18n keys, so the roles editor shows a readable line for it in every language. Without it, the permission is titled with the raw component name.

::tabs
:::tabs-item{label="Good" icon="i-lucide-check"}
```ts [src/pages/routes.ts]
static graph = CustomComponent("ApiRouteGraph")
  .options({ fetchUrl: "/api/routes/graph", periodScope: "api" })
  .meta({
    name: "$api.routes.graph.name",
    description: "$api.routes.graph.description",
    icon: "i-ph-graph",
  });
```
:::

:::tabs-item{label="Bad" icon="i-lucide-x"}
```ts [src/pages/routes.ts]
// The roles editor shows "ApiRouteGraph", untranslated, with no icon.
static graph = CustomComponent("ApiRouteGraph").options({ fetchUrl: "/api/routes/graph" });
```
:::
::

Add the keys to every locale file of your frontend layer. Use `$` keys for every other text too: page names, titles, labels, button labels.

## When a design is involved

When you hand an agent a mockup or a screenshot, it follows the [design-fidelity protocol](/docs/ai-and-claude-code/design-fidelity): one framing question, then a decision per component — DMS block or custom — with a preview of the DMS option.
