---
title: "Sketch check"
description: How the mockup compiler and the preview_blocks tool check a sketch's HTML and CSS, and how another process runs the same check through @antelopejs/dms/sketch.
mode: reference
---

A [sketch](/docs/ai-and-claude-code/mockups#sketches) is static HTML and CSS that the viewer draws in a sandboxed frame. The frame's CSP stops loads, but not a link out, so the check below is what keeps a sketch from navigating or loading outside the frame.

The mockup compiler parses a sketch's `html` with an HTML parser, as the frame's body and with scripting off, the way the sandboxed frame reads it. It then checks the tree it read against an allowlist:

- Elements: text and layout HTML (headings, paragraphs, lists, tables, `div`, `span`, `img`, `figure`, `details`, `button`, `input`, `textarea`, `style` and the like), an SVG subset for drawings (`svg`, `g`, `path`, shapes, `text`, gradients, `clipPath`, `mask`, `pattern`, `marker`, `use`, `image`, `a`, `style`), and a MathML subset for formulas. Any other element is refused by name, `<script>`, `<iframe>`, `<object>`, `<embed>`, `<link>`, `<base>`, `<meta>`, `<form>`, `<template>`, `<noscript>`, `<foreignObject>`, `<set>` and `<animate>` among them.
- Attributes: `id`, `class`, `style`, `title`, `lang`, `dir`, `role`, `hidden`, `tabindex`, `aria-*` and `data-*` on any element, the SVG presentation and geometry attributes, and the few each HTML element needs (`alt` and `width` on `<img>`, `colspan` on a cell, `value` on `<progress>` and the like). Any other attribute is refused by name, every `on*` handler among them.
- URLs: `href` on `<a>` and SVG `<a>` or `<use>` may only be an `#anchor`. `src` on `<img>` and `href` on SVG `<image>` may only be a `data:image/` URL.
- At most 524,288 characters in each of `html` and `css`, 4,096 tags, 64 attributes on one tag and 256 levels of nesting.

CSS is read from `css`, from the `<style>` elements and `style` attributes of the parsed tree, and from every SVG and MathML attribute, which SVG reads as CSS. A CSS tokenizer reads it as the CSS Syntax spec does, escapes, newlines and comments included, and the compiler refuses:

- A string or `url()` a browser reads as broken, such as a string a newline ends.
- A CSS `@import`.
- A `url()` that is not an `#anchor` or a `data:image/` URL, read as the browser reads it: `url(\22 #a\22 )` is the relative URL `"#a"` and is refused.
- A `url()` or `src()` whose URL is not a quoted string, such as `src(var(--x))`.
- A string in an `image()`, `image-set()` or `cross-fade()` that is not an `#anchor` or a `data:image/` URL.
- A `var()`, `env()` or `attr()` inside a `url()`, `src()` or image function, and an `attr()` read as a URL.
- A string inside a function the check does not know. Strings stay allowed outside functions (`content`, `font-family`, `quotes`) and inside `format()`, `local()`, `tech()`, `symbols()`, `counters()`, `attr()`, `type()` and `:lang()`.
- CSS the tokenizer cannot read, such as a name of more than about 150,000 characters.
- In `css`, markup such as `</style>` that would end the style element it is drawn in.

A sketch that passes is emitted with its `html` written back from the tree the parser read, without comments, so the frame draws what was checked. The written-back markup can differ from the source byte for byte: quotes are normalized, and an element the parser closed or reopened is written as it read it. Markup the parser would read differently once written back is refused. A refused sketch is emitted with an empty `html` and no `css`, and each refusal is an issue.

The MCP `preview_blocks` tool refuses a sketch by the same check. Another process runs it through `@antelopejs/dms/sketch`, which needs only `zod`, `parse5` and `@csstools/css-tokenizer` and loads without the AntelopeJS runtime:

```ts
import { checkSketch } from "@antelopejs/dms/sketch";

const checked = checkSketch({
  html: '<p class="note">Packed</p>',
  css: ".note{color:var(--sketch-accent)}",
});
if (!checked.ok) {
  throw new Error(checked.refusals.map(({ what }) => what).join("; "));
}
const drawn = checked.sketch;
```

`checkSketch` answers the sketch to draw, its `html` written back from the parsed tree, or one refusal per field and rule. `sketchRefusals` answers only the refusals, and an empty list for a sketch that may be drawn.
