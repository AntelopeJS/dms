An AI agent can build AntelopeJS DMS pages in two places. The DMS AI assistant runs inside your dashboard. Your own coding agent, such as [Claude Code](https://claude.com/claude-code) or [Codex](https://developers.openai.com/codex), runs in your terminal. Both read the same skills and call the same `dms` MCP tools, so both build the same way.

::important
**Run your own Claude Code or Codex? Install the `antelopejs` plugin first.** Without it, your agent has none of the DMS skills and does not know how to declare a page, pick a block or use the builder tools.

```bash [Claude Code]
claude plugin marketplace add AntelopeJS/agent-skills
claude plugin install antelopejs@antelopejs
```

```bash [Codex]
codex plugin marketplace add AntelopeJS/agent-skills
codex plugin add antelopejs@antelopejs
```

Then run `ajs project dev` once in your project. It writes a `dms` server into `.mcp.json` for Claude Code and `.codex/config.toml` for Codex, which gives your agent the builder, database, page and mockup tools. [Install the plugin](/docs/ai-and-claude-code/coding-agent/install) covers the details.
::

## Pick where the agent runs

| | DMS AI assistant | Your coding agent |
| --- | --- | --- |
| Where it runs | A chat panel in the dashboard, for the platform owner | Claude Code or Codex in your terminal |
| What you install | The [`@antelopejs/dms-assistant`](/docs/modules/assistant/introduction) module | The `antelopejs` plugin |
| Where the skills come from | The assistant loads them from your installed packages | The plugin links them into `.claude/skills/` and `.agents/skills/` |
| Where the tools come from | The `dms` MCP server of `@antelopejs/dms` | The same server, through `.mcp.json` or `.codex/config.toml` |
| Extra in the chat | Buttons for answers, the mockup viewer beside the chat | None |

The tools exist only in development. `ajs project dev` and `ajs project run` start the server, and a production backend serves none of them.

## Skills ship with the code they describe

A skill is a short instruction file that an agent loads when a task matches its description. A package declares its skill folders under `antelopeJs.skills` in its `package.json`, so a skill always matches the version you installed. Three kinds of package ship skills:

| Package | Skills |
| --- | --- |
| `@antelopejs/core` | `antelopejs`, `ajs-cli`, `ajs-consume-interface`, `ajs-author-interface` |
| `@antelopejs/dms` and `@antelopejs/dms-frontend` | `dms`, `dms-project`, `dms-module`, `dms-auth` and `dms-frontend` |
| Each `dms-*` module | One skill per module, such as `dms-mailing`. `@antelopejs/dms-assistant` ships two. |

The `antelopejs` plugin adds skills of its own on top, such as `antelopejs:dms-pages`, `antelopejs:dms-best-practices` and `antelopejs:dms-mockup`. The [skill catalog](/docs/ai-and-claude-code/coding-agent/skill-catalog) lists every skill and when it loads.

## Mockups come before pages

For a new app or a new screen, the agent first draws a mockup: real DMS blocks over sample data, saved in `mockups/<name>/spec.json`. You click through it and pin comments on it. The agent applies your comments, and builds the real pages once you approve. [Mockups](/docs/ai-and-claude-code/mockups) explains the flow.
