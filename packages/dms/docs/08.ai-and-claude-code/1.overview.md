# AI & coding agents

The DMS is built to be developed with an AI agent. A suite of **skills** — short, versioned instructions an agent loads on demand — teaches it the framework, the DMS and every module you install: how to declare a page, which block draws what, how permissions are derived, how to run the dev servers. The same skills serve [Claude Code](https://claude.com/claude-code) and [Codex](https://developers.openai.com/codex) in your terminal and the [dms-ai assistant](/docs/ai-and-claude-code/dms-ai) inside your dashboard.

::tip
Start with [Install the plugin](/docs/ai-and-claude-code/install): one plugin, then every package you install brings its skills. The [skill catalog](/docs/ai-and-claude-code/skill-catalog) lists what you get.
::

## Three layers, no duplicates

Each skill lives next to the code it describes, so it ships and versions with it. The `antelopejs` plugin for Claude Code and Codex ([agent-skills](https://github.com/AntelopeJS/agent-skills)) holds no skill: it **syncs** the skills of all three layers into your project.

| Layer | Where it lives | Skills |
| ----- | -------------- | ------ |
| **Framework** | `@antelopejs/core`, in its `skills/` folder | `antelopejs`, `ajs-cli`, `ajs-consume-interface`, `ajs-author-interface`. |
| **DMS** | `@antelopejs/dms`, in its `skills/` folder, and `@antelopejs/dms-frontend` | `dms`, `dms-project`, `dms-module`, `dms-pages`, `dms-auth`, `dms-best-practices`, and `dms-frontend` for the `ajs dms` CLI and frontend modules. |
| **Modules** | Each `dms-*` module, declared in its `package.json` | One skill per module (`dms-mailing`, `dms-media`…); `dms-ai` adds `dms-builder-safe` and `dms-ai-code-mode` for its two generation modes. |

::tip
The [skill catalog](/docs/ai-and-claude-code/skill-catalog) lists every skill with the package that ships it, when the agent reaches for it, and the page that covers the same ground.
::

## The DMS skills

| Skill | Reach for it to |
| ----- | --------------- |
| `dms` | Get the mental model and be routed to the right skill. |
| `dms-project` | Set up a project that uses the DMS (`antelope.config.ts`, lifecycle, frontend) and start, stop or restart its dev servers. |
| `dms-pages` | Declare pages and compose blocks, data types and the routes that feed them. |
| `dms-auth` | Protect routes and pages, register permissions, work with users, roles and tenants. |
| `dms-module` | Package a distributable DMS module. |
| `dms-best-practices` | Describe pages as blocks, propose a custom block before building it and build only the missing one, give it `.meta()`, and follow the design-fidelity protocol. |
| `dms-frontend` | Run any `ajs dms` command, write a frontend module, and deploy the frontend server. |

## How skills reach your agent

::card-group
:::card{title="Claude Code and Codex" icon="i-lucide-terminal" to="/docs/ai-and-claude-code/install"}
Install the `antelopejs` plugin once; it links every package's skills into `.claude/skills/` or `.agents/skills/`.
:::

:::card{title="dms-ai assistant" icon="i-lucide-bot" to="/docs/ai-and-claude-code/dms-ai"}
Nothing to install: the assistant loads the skills of every loaded module and of the project's dependencies.
:::
::
