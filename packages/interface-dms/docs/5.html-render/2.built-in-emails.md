# Built-in Emails

## Overview

The DMS sends seven emails of its own. Each one is a template registered through [`RegisterHtmlTemplate`](/docs/interfaces/html-render/introduction#registerhtmltemplate), rendered by the frontend server from a Vue component in `frontend-vue/layers/dms-layout/app/emails/`, and delivered through `@antelopejs/interface-email`. They share one frame, `EmailLayout`: the branding logo, a white card, a heading, the body, a separator and a footer.

| Template | Sent when | Sent to | English subject |
| -------- | --------- | ------- | ------- |
| `EmailUserValidation` | A user signs up while `auth.mustValidateEmail` is on, or asks for a new code | The new account's address | `Verify Your Email` |
| `EmailResetPassword` | A user asks for a password reset | The account's address | `Reset Your Password` |
| `EmailTwoFactor` | A user signs in with email as their second factor | The account's address | `Your verification code` |
| `EmailAdminInvite` | A member is invited to the platform or to a workspace | The invited address | `You're invited to join <workspace> on <platform>`, shorter when a name is unknown |
| `EmailChangeVerification` | A user asks to change their sign-in email | The new address | `Confirm your new sign-in email` |
| `EmailChangeNotice` | The same request | The current address | `Your sign-in email is being changed` |
| `EmailExportReady` | A data export delivered by email has finished | The user who asked for it | `Your data export is ready` |

Each email, subject included, is written in the recipient's language, English or French (see [Language](#language)).

These names are taken: pick other names for your own emails. To change what a built-in email looks like, see [Replacing a built-in email](#replacing-a-built-in-email).

## Props

What the backend passes to each template. A template that replaces a built-in one receives the same props.

| Template | Props |
| -------- | ----- |
| `EmailUserValidation` | `userName`, `validationCode`, `expiresInHours` (from `auth.emailValidationTokenLifetime`), `expiresIn` |
| `EmailResetPassword` | `userName`, `resetCode`, `expiresInHours` (from `auth.passwordRecoverTokenLifetime`), `expiresIn` |
| `EmailTwoFactor` | `userName`, `verificationCode` |
| `EmailAdminInvite` | `email`, `signupLink`, `expiresInDays`, and when known `workspaceName`, `inviterName`, `platformName` (`meta.title`) |
| `EmailChangeVerification` | `userName`, `newEmail`, `code`, `expiresInHours` (from `auth.emailValidationTokenLifetime`), `expiresIn` |
| `EmailChangeNotice` | `userName`, `newEmail` |
| `EmailExportReady` | `userName`, `downloadLink`, `expiresInHours`, `expiresIn`, `partial`, `failedSources` (the export sources that could not be included) |

`userName` is the user's name, or their email address when they have none. `expiresInHours` is the lifetime as a number, for the template to word in the recipient's language; `expiresIn` is the same lifetime already worded in English (`24 hours`), kept for templates written before `expiresInHours`.

## Language

Each email is written in the recipient's language: the account's `language`, or for an invitation the language it was sent in. English and French are supported; any other language falls back to English.

The body text lives in the `dms-layout` locale files (`i18n/locales/layout-*.json`), under one key per email (`emails.user_validation`, `emails.reset_password`, `emails.two_factor`, `emails.admin_invite`, `emails.email_change_verification`, `emails.email_change_notice`, `emails.export_ready`) plus the shared `emails.common`. Locale files merge in module priority order, so a module registered with a priority above the DMS's (`0`) can reword any of these keys in its own `i18n/locales/*.json`:

```json [frontend-vue/i18n/locales/acme-en-GB.json]
{
  "emails": {
    "reset_password": {
      "footer": "Didn't ask for this? Contact support@acme.test."
    }
  }
}
```

The subject is set by the backend, which sends it in the same language. It cannot be reworded from a module.

## Logo

Every built-in email draws `branding.logo.email.light` from the app config, or `branding.logo.default.light` when no email logo is set (see [Email Layout](/docs/interfaces/html-render/introduction#email-layout)), with `publicLogoOnly` on. The logo shows only when a mail client can load it: a PNG or JPEG served from a public `http(s)` address. The default DMS logo is an SVG, which Gmail and Outlook refuse, so out of the box the emails carry no logo. To show yours, set an `email` logo in your layer's `app/app.config.ts`, and serve the dashboard from a public `clientBaseUrl`:

```ts fragment [frontend-vue/app/app.config.ts]
export default defineDmsAppConfig({
  branding: {
    logo: {
      email: {
        light: "/branding/logo-email.png",
        dark: "/branding/logo-email-dark.png",
      },
    },
  },
});
```

The loader hands every layer's `app/app.config.ts` to the email renderer too (from the 0.6.0 release of `dms-frontend`), merged in module priority order, so a module registered with a priority above the DMS's (`0`) wins. `dark` is optional: when it passes the same check and differs from `light`, the header becomes a `<picture>` whose dark source the mail clients that follow the reader's dark mode pick, and the others draw `light`.

## Replacing a built-in email

The render server looks a template up by its file name, in module priority order, and renders the first match. A module registered with a `priority` above the DMS's (`0`, see [`AddFrontendModule`](/docs/interfaces/core/pages-and-modules#addfrontendmoduleoptions)) therefore replaces a built-in email by shipping a component of the same name in its `dms.email.ts`:

```ts fragment [frontend-vue/dms.email.ts]
export const serverEmailTemplates = import.meta.glob("./app/emails/**/*.vue");
```

```vue [frontend-vue/app/emails/EmailResetPassword.vue]
<script setup lang="ts">
import { useI18n } from "vue-i18n";
import EmailLayout from "#dms-layout/app/emails/components/EmailLayout.vue";
import EmailOTP from "#dms-layout/app/emails/components/EmailOTP.vue";

defineProps<{ userName: string; resetCode: string; expiresInHours: number }>();

const { t, locale } = useI18n();
</script>

<template>
  <EmailLayout :title="t('emails.reset_password.title')" :lang="locale" public-logo-only>
    <EText>{{ t("emails.common.greeting", { name: userName }) }}</EText>
    <EText>Use this code to choose a new Acme password:</EText>
    <EmailOTP :code="resetCode" :expires-in="t('emails.common.hours', expiresInHours)" />
  </EmailLayout>
</template>
```

The replacement receives the props listed in [Props](#props) and keeps the backend's subject. Do not register the name again with `RegisterHtmlTemplate`: the DMS already sends it. At equal priority the first module by id wins, so set the priority explicitly rather than relying on it.
